## A2 — 종료상태 분해

운영 워커 경로(`_fit_alpha_range`)를 그대로 부른다. 기준 설정이 §6 의 실측을
재현하는지 먼저 확인했다.

| | 문서 §6 | 이 스윕 base | 차이 |
|---|---|---|---|
| 행 수 | 8446 | **8446** | 0 |
| CONVERGED | 5553 (65.75 %) | 5520 (65.36 %) | −33 |
| STEP_LIMITED | 1808 (21.41 %) | 1809 (21.42 %) | +1 |
| AT_BOUND | 1085 (12.85 %) | 1117 (13.23 %) | **+32** |
| 비최적 | 34.26 % | 34.64 % | +0.38 pp |
| NO2 중앙 (ppb) | 2.204256 | 2.20911 | +0.22 % |
| shift 중앙 (px) | −1.9629 | −1.978 | −0.015 |

문서의 실측 스크립트는 저장소에 없다(부록 A-6: "일회성이라 넣지 않았다"). 이 스윕은
**진짜 운영 워커**를 부르므로 엔진 조립(배율·정규화)과 첫 스캔 에탈론 검출이 그쪽
일회성 스크립트와 완전히 같지는 않다. **비최적 합계가 0.4 pp 안에서 재현**되므로
기준선으로 쓴다.

### 표

|---|---|---|---|---|---|
| **base** (상자 ±5 · step 0.5 · poly 3) | 65.36 % | 21.42 % | 13.23 % | **34.64 %** | `sh,sq` 645 · `sq` 472 |

**범위**: 비최적 **13.06 – 34.70 %**. 스텝 리밋 off 를 빼면 **34.60 – 34.70 %**.

### 지시서가 콕 집어 물은 것: 스텝 리밋 off 에서 21.4 %는 어디로 가나

**전부 CONVERGED 로 간다. AT_BOUND 로는 가지 않는다.**

```
CONVERGED     65.36 %  →  86.94 %   (+21.58 pp)
STEP_LIMITED  21.42 %  →   0.00 %   (−21.42 pp)
AT_BOUND      13.23 %  →  13.06 %   (−0.17 pp)
```

즉 **보폭 제한에 걸려 있던 핏은 보폭을 풀면 상자 안에서 멈춘다** — 허용범위가 최적점을
못 담아서 걸린 게 아니다. 대신 `steplimit_off` 에서 shift p99 가 −0.053 → +0.562 px
로 올라가고 p01 이 −2.695 → −2.942 로 내려간다(폭이 넓어진다).

### 상자 축이 평평한 이유 — 설계상 그렇다

`step_limit 0.5` 가 걸려 있으면 상자는 언제나 `앵커 ± 0.5` 와 전역 `sh_val` 의
**교집합**이고, 실측 shift 가 −2.70 ~ −0.05 px 라 전역 상자(±5 이상)는 **한 번도
닿지 않는다**. 그래서 상자를 ±4 로 좁히든 ±8 로 넓히든 같은 계를 푼다.

> **상자 축은 스텝 리밋이 켜져 있는 한 정의상 무효다.** 이 축을 의미 있게 재려면
> `상자 × steplimit_off` 칸이 필요한데, 그건 OAT 설계 밖이라 돌리지 않았다.
> 필요하면 `--only` 로 한 조합씩 추가할 수 있다(조합당 약 4 분).

### AT_BOUND 는 squeeze 다 — 부록 A-1 의 정정이 확인된다

`steplimit_off` 에서 AT_BOUND 1103 건 중 **1094 건이 `NO2_sq` 단독**, 8 건이 `sh,sq`,
**`NO2_sh` 단독은 1 건**이다. 기준 설정에서 `sh,sq` 가 645 건으로 보이는 것은 shift 가
**보폭 창**(전역 상자가 아니라)에 동시에 붙어 있기 때문이고, 전역 경계를 만든 것은
squeeze 다 — shift 는 p01 −2.695 · p99 −0.053 로 ±5 근처에도 못 간다.
