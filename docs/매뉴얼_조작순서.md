# Augur 조작 매뉴얼 — 캠페인 데이터 처리 처음부터 끝까지

대상: 프로그램을 **운용**하는 사람(코드를 고치지 않는 사람). 설치·폴더 구조·
용어는 `README.md`(개발자용) 참조. 이 문서는 "raw .dat 폴더를 받았을 때
농도 그림이 나올 때까지" 버튼 순서를 따라간다.

> 스크린샷은 추후 실제 운용 화면으로 채운다(각 절의 `[스크린샷: …]` 자리).
> GUI 코드는 수정 후 **앱 재시작**이 필요하다(모듈 캐시).

---

## 0. 준비물 체크리스트

| 항목 | 예 | 비고 |
|---|---|---|
| raw `.dat` 폴더 | `…\CAESAR_Cold\2026-05\` | 장비가 1시간마다 1파일 |
| 파장보정 파일 | `Calib_*_Hg_4line_*.txt` | Hg 램프로 만든 픽셀→nm |
| ILS 적용 레퍼런스 | `Ref_NO2_Dynamic-ILS-Applied.dat` 등 | 종별 단면(뭉갬 적용본) |
| 피팅 시나리오 JSON | `scenarios/*.json` | 창·poly·shift 모드 일괄 |
| (있으면) 기존 `R_<채널>.npz` | `Output\R\R_cold.npz` | R(t) 누적본 — 증분 갱신됨 |

실행: `python main.py` 또는 `Augur_실행.bat`.

## 1. Setup — 시나리오 로드와 레퍼런스 잠금

1. 좌측 패널 **채널 탭바의 📋 버튼**으로 시나리오 JSON 로드
   (핏 창·poly 차수·기체 목록·shift/squeeze 모드가 전 채널에 한 번에 들어간다).
2. 파장보정이 함께 로드됐는지 확인(없으면 `Load X-axis`로 직접).
3. **🔒 Lock References (Commit)** — 레퍼런스를 엔진에 잠근다.
   이후 창/레퍼런스를 바꾸면 다시 Lock 해야 한다.

`[스크린샷: Setup 탭 좌측 패널 + Lock 버튼]`

## 2. R Calibrator — 거울 반사율 R(t) 만들기

Setup 탭 **📐 R Calibrator** 버튼.

1. **🔄 Load channels from left panel** — 좌측 패널 채널 설정을 그대로 가져온다.
2. 채널별 Raw Dir(ZA/He 주입이 들어있는 raw 폴더)을 지정.
3. **▶ Start** — 스캔·R 계산. `Auto-update α R(t) npz` 체크(기본 ON)면
   `R_<채널>.npz`에 **증분 머지**된다(재계산 없음, 기존 knot 보존).
4. **🔍 Verify npz** — 빈 날(그 구간은 보간으로만 채워짐)·미계산 파일·
   **계단 후보**(step guard)를 읽기 전용으로 점검.
5. 거울 청소/재정렬을 한 날이 있으면 **⛓ R(t) Breaks…** 에 그 시각을 입력
   ("YYYY-MM-DD HH:MM"). α 생성 시 그 시각을 가로질러 보간하지 않는다
   (knot 삭제 없음 — 보간 분절만).
6. **🔁 Rebuild npz (full)** 은 설정(cavity/RL/R창)을 바꿨거나 npz가 깨졌을 때만
   (전체 재계산·덮어쓰기 — 평소엔 Start 증분으로 충분).

주의: R-cal은 순수 주입 flag(ZA 500/He 510)만 쓴다. 좌측 패널 flag를 바꿔도
R-cal은 따라가지 않고 경고만 띄운다.

`[스크린샷: R Calibrator — Start/Verify/Breaks 버튼 열]`

## 3. Alpha Generator — raw → α 스펙트럼

Setup 탭 **🧪 Alpha Generator** 버튼.

1. **📁 Select Raw Folder**(또는 파일 선택)로 처리할 raw 지정.
2. 채널 행에서 raw 채널 ↔ 어느 채널 탭 설정으로 α를 만들지 확인.
3. 채널 행의 **📈** 버튼으로 2단계에서 만든 `R_<채널>.npz`를 R(t)로 지정
   — 지정하면 α가 시간보간된 R(t)를 쓴다(권장). 미지정 시 자체 R로 폴백.
4. **💾 Output Folder** 지정 → **🧪 Generate Alpha**.
5. 로그에서 확인할 것:
   - `[R(t) load] N knots` — npz가 실제로 적용됐는지
   - `[STEP GUARD] …` — 계단 후보/수동 분절이 반영됐는지
   - `[WARN] HK not recovered …` — 기본 T/P로 떨어진 스캔 수(많으면 조사)
6. 출력: 날짜별 폴더에 `*_alpha_trace.dat` (60초 평균, 헤더에 보정 이력 기록).

`[스크린샷: Alpha Generator — R(t) 픽커와 Generate 버튼]`

## 4. 피팅 준비 — 데이터 로드와 옵션

Analysis Monitor(좌측 패널) 기준.

1. **Load Data** 로 3단계의 `*_alpha_trace.dat` 로드(여러 날 가능).
2. **Time shift(h)**: 출력 시각에 더할 시간. 예) 2026 여수: Cold=0(UTC 유지),
   Hot 5월=−9(KST→UTC). 시나리오·기간에 따라 확인.
3. 옵션(캠페인 운용 기본):
   - **±Neg** ON — 0 근처 비편향(음수 농도 허용; 평균이 참값 주위로).
   - **Auto QC** ON, K=6 — log-MAD 기반 자동 RMS 컷(비파괴 flag).
   - **⏱ Settling** N=3 — 주입 복귀 직후 캐비티 미충전 스캔 flag(농도 저편향 방지).
4. **🧪 Test Fit (1 scan)** 으로 첫 스캔을 미리 핏해 본다:
   - 측정 vs 핏, 레퍼런스 기여, 잔차 3패널
   - `etalon-gas collinearity` 한 줄 — ⚠(주황)이면 etalon과 기체 지문이
     닮아 오차가 부풀 수 있다는 뜻(값은 그대로 — 창/기체 구성 재검토 신호).

`[스크린샷: 좌측 패널 옵션 + Test Fit 팝업]`

## 5. RUN — DOAS 피팅 실행과 저장

1. **RUN** → 설정 요약 확인창에서 **▶ Start**.
2. 진행 중: 테이블·실시간 농도 그래프. 문제가 보이면 STOP.
3. 완료 후 **Save** — 자동 버킷 규칙으로 저장된다:
   `저장폴더\{핏config}\{YYMMDD}\{neg_o|neg_x}\{QCk6 등}\{날짜}_{채널}_{세팅태그}.dat`
   - `{핏config}` = 저장에 포함된 채널들의 핏 윈도우 결합. 예:
     `ch1_429.5~461.9__ch2_444.1~470.6__ch3_438.4~475.8` — 탐색기에서 폴더만
     봐도 어떤 윈도우로 핏한 자료인지 바로 식별. 윈도우가 다른 실험은 최상위에서 분리.
   - 같은 날+같은 세팅 재핏 시 기존 파일은 `_archive/`로 자동 보존.
   - 파일 헤더(#)에 모든 세팅 + `Etalon-Gas Collinearity` 진단이 박힌다.

`[스크린샷: RUN 진행 + 저장 결과 폴더 구조]`

## 6. Result Lab — 결과 열람·QC·계산

1. **📅 날짜 로더**로 기간을 고르면 일별 파일이 자동 머지되어 열린다
   (머지 캐시는 `_derived/`).
2. QC 재적용: K 값을 바꿔 다시 flag(비파괴 — 원본 값 삭제 없음).
3. **계산기**: 다단계 수식으로 파생량 생성. 예) 핫 채널:
   **CH1=ANs(300°C), CH2=PNs(180°C) → ANs = CH1 − CH2** (시간 자동 정렬).
4. 자르기/병합 결과는 `_derived/`에 저장(원본 불변).

`[스크린샷: Result Lab — 날짜 로더와 계산기]`

## 7. Plot Maker — 출판용 그림

1. 시리즈 추가(트리 검색·드래그 순서) → 날짜 프리셋으로 기간 지정.
2. 규약(박사님 그림 규약): X 날짜범위 입력으로 xlim·눈금 통일, 데이터 공백은
   마커만(Line=none), 라벨에 셀/종 명시, 종별 색 통일(시계열↔diurnal).
3. **🔍 Preview** = 출판 결과와 동일 렌더. 확인 후 **Publish**
   (여러 날짜 구간은 **Batch Publish**).

`[스크린샷: Plot Maker — Preview vs Publish]`

## 8. 상태 점검·문제 해결

| 증상/작업 | 할 일 |
|---|---|
| 코드 수정 후 전체 점검 | `python tools/validate_pipeline.py` → 4 PASS·0 FAIL 확인(데이터 없는 머신은 `--no-data`) |
| 시각화 수정 후 | `python tools/validate_plotmaker.py` → 24/24 |
| GUI가 수정 반영 안 함 | 앱 재시작(모듈 캐시) |
| 크래시 | `logs/crash.log`, 세션 로그 `logs/session_*.log` |
| α가 이상함 | 생성 로그의 `[R-CAL]`/`[STEP GUARD]`/`[WARN]` 줄부터. 헤드리스 vs GUI가 다르면 **입력 파일 목록 diff 먼저**(비측정 .dat 혼입 이력 있음) |
| R(t)에 계단 경고 | 실제 이벤트(청소 등)면 Breaks에 시각 등록, 아니면 해당 구간 주입 품질 확인 |

데이터 무결성 원칙(전 단계 공통): 지우지 않는다 — flag만 한다. 자동 배제는
전부 옵트인이고, 무엇이 얼마나 빠졌는지 %가 로그·헤더에 남는다.
