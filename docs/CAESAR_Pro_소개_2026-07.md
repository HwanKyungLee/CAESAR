## 0. 한 장 요약 — 이 프로그램이 하는 일

측정 장비(CAESAR)는 1초마다 "빛의 스펙트럼" 한 줄을 파일에 기록한다. 그게 전부다.
농도는 어디에도 적혀 있지 않다. **CAESAR Pro는 그 빛의 기록을 대기 중 미량기체
(NO₂, 글리옥살(CHOCHO), PAN류(PNs), 질산알킬류(ANs) 등)의 농도 시계열로 바꿔 주는
프로그램**이다. 단위는 ppb(10억분율)·ppt(1조분율) — 공기 분자 10억 개 중 몇 개
수준의 흔적을 세는 일이라, 계산 과정의 작은 실수 하나가 결과 전체를 틀리게 만든다.

기존에는 이 변환을 두 프로그램에 나눠서 했다: 박사님이 만든 **MATLAB 스크립트**가
빛 기록 → 흡광 스펙트럼 변환을, 독일 하이델베르크의 **DOASIS**가 흡광 스펙트럼 →
농도 피팅을 맡고, 그 사이를 사람이 파일로 날랐다. CAESAR Pro는 이 두 단계를 하나의
GUI 프로그램으로 통합하되, **기존 결과와 숫자가 일치하는지 단계마다 대조 검증**한
뒤에만 대체했고, 그 위에 기존에 없던 것들(반사율의 시간 변화 추적, 병렬 처리,
지우지 않는 품질 관리, 결과마다 계산 조건 자동 기록)을 더했다.

## 1. 측정 원리 — 아무것도 모르는 사람을 위한 출발점

### 1.1 색으로 기체를 세는 법

기체 분자는 저마다 **특정 파장(색)의 빛만 골라 흡수**한다. 예컨대 NO₂는 파란색-보라색
영역의 빛을 잘 흡수하는데(그래서 NO₂가 짙은 도시 매연이 갈색으로 보인다), 어느
파장을 얼마나 흡수하는지의 상세한 곡선은 분자마다 달라서 **지문**처럼 쓸 수 있다.
빛을 공기에 통과시킨 뒤 "어떤 파장이 얼마나 깎였나"를 보면, 그 지문 모양으로 **어떤
기체가**(정성), 깎인 깊이로 **얼마나 있는지**(정량)를 알 수 있다. 이것이 흡수분광법이고,
여러 기체의 지문이 겹쳐 있는 스펙트럼을 수학적으로 분리해내는 기법이 DOAS다.

문제는 양이다. 대기 중 NO₂는 10억 분의 몇 수준이라, 빛이 공기 1 m를 지나도
깎이는 양이 사실상 0이다. 흡수량은 빛이 지나간 **경로 길이에 비례**하므로,
미량기체를 보려면 경로를 수 km로 늘려야 한다.

### 1.2 거울 두 장으로 경로를 수 km로 — 캐비티(cavity)

수 km짜리 관을 만들 수는 없으니, 대신 **반사율 99.98% 수준의 거울 두 장을 마주
보게** 놓는다(이 구조가 캐비티다). 안에 들어간 빛은 거울 사이를 수천 번 왕복한
뒤에야 빠져나오고, 그 동안 지나간 거리의 합이 유효 경로가 된다. 1 m 캐비티에
R = 99.98% 거울이면 유효 경로는 대략 1/(1−R) = 5,000배, 즉 5 km에 달한다.
광원으로 레이저 대신 LED(넓은 파장 대역)를 쓰는 방식이 BBCEAS
(Broadband Cavity-Enhanced Absorption Spectroscopy)다. 넓은 대역을 쓰기에
여러 기체의 지문을 한 번에 볼 수 있다.

이 증폭 원리에서 소프트웨어의 숙제가 바로 나온다: **농도의 절대값은 경로 길이를
알아야 나오고, 경로 길이는 거울 반사율 R이 결정한다.** 그런데 R은 상수가 아니다 —
거울이 며칠 사이에도 미세하게 오염되며 변한다. R을 0.01%만 틀려도 경로가 수십 %
틀어진다. 그래서 R을 "재는" 절차가 측정의 일부다(§4.3).

### 1.3 소프트웨어가 알아야 하는 세 가지

측정된 빛의 밝기 I(λ)를 농도로 바꾸려면 세 가지 기준량이 필요하다:

1. **I₀(λ) — 기체가 없을 때의 밝기.** "깎였다"고 말하려면 안 깎였을 때의 기준이
   필요하다. 장비는 주기적으로 깨끗한 공기(제로에어, ZA)를 주입해 이 기준을 얻는다.
   LED 밝기는 시간이 지나며 흘러내리므로(드리프트) 이 기준도 시간을 따라가야 한다.
2. **R(λ) — 거울 반사율.** 경로 길이의 근원. 헬륨(He)과 제로에어(ZA)를 번갈아
   주입해 역산한다(§4.3). 역시 시간에 따라 변한다.
3. **Rayleigh 산란 — 공기 자체가 빛을 흩뜨리는 효과.** 기체 "흡수"가 없어도 공기
   분자는 빛을 산란시켜 빼앗는다(하늘이 파란 이유와 같은 물리). 이 효과는 흡수처럼
   보이므로 정확히 계산해서 빼야 하고, 공기 밀도(온도·압력)에 의존하므로 행마다
   실측 T/P로 계산해야 한다(§4.2).

이 세 가지를 어떻게 다루느냐가 BBCEAS 자료처리의 품질을 가른다. 원리 자체
(Fiedler et al. 2003; Washenfelder et al. 2008)는 확립되어 있고, 실제 결과를
좌우하는 것은 **운영상의 세부**다: 거울 반사율이 흐르고, He/ZA 주입의 전환 순간이
보정을 오염시키고, 구름·저광량 스캔이 피팅을 폭주시키고, 수백 GB의 raw 파일을
몇 번이고 재처리해야 한다. CAESAR Pro는 이 세부를 다루는 프로그램이다.

## 2. 설계 목표

ppb·ppt 스케일 연구의 특성에서 나온 세 가지 원칙 위에 설계했다.

1. **물리 우선, 통계 보조** — 데이터를 거르는 근거는 가능한 한 물리적 사실(주입
   상태 플래그, 실측 온도·압력, He/ZA 밝기 대비)에서 나오고, 통계적 문턱값이
   필요할 때는 분포에서 자동으로 유도(robust MAD, §6)해 임의의 매직넘버를
   최소화한다.
2. **비파괴** — 어떤 자동 처리도 원본 값을 지우지 않는다. 제외는 "표시(플래그)"로
   하고, 원본은 항상 복원 가능하며, 몇 %가 왜 제외됐는지 숫자로 보고한다.
   미량기체 연구에서 과도한 필터링은 부족한 필터링보다 위험하다 — 지워진 데이터는
   돌아오지 않고, "좋아 보이는" 데이터만 남기는 필터는 결과를 원하는 방향으로
   왜곡한다.
3. **재현성** — 같은 입력 + 같은 세팅이면 언제 누가 돌려도 같은 출력. 이를 말이
   아니라 구조로 보장한다: 모든 결과 파일 머리에 코드 버전(git 해시)과 사용된
   세팅 전체가 자동 기록된다(§6-5).

## 3. 전체 파이프라인

원본 데이터는 LabVIEW가 기록하는 시간당 1개의 `.dat` 파일이다. 한 행이 1초 스캔
하나이고, 행 안에 채널별 스펙트럼 2048픽셀 + 하우스키핑(온도, 압력, 주입 상태
플래그, 시각)이 들어 있다. 처리 흐름:

```
raw .dat (1시간/파일, 행 = 1초 스캔)
   │  ① 파싱: 스펙트럼 + 온도/압력/플래그 + 시각
   ▼
② R Calibrator ──→ 거울 반사율 시계열 R(t)        ← He/ZA 주입쌍마다 한 점
   │
   ▼
③ Alpha Generator: I₀(t) 보간 + R(t) 보간 + Rayleigh 보정
   │              → 흡광계수 α(λ, t), 60초 평균     (*_alpha_trace.dat)
   ▼
④ DOAS 피팅: 기체 지문들을 α에 맞춰 농도 산출 (채널별 병렬)
   │              → 농도 ppb + 오차 + 품질지표
   ▼
⑤ 자동 QC(비파괴 플래그) → 날짜/세팅별 자동 저장 → Result Lab / Plot Maker
```

중간 산물인 α 파일이 이 구조의 허리다. α 파일은 자기 파장축과 보정 이력(어느 R을
썼는지, I₀ 모드가 뭐였는지)을 스스로 지니고 있어 **단계별로 독립 검사가 가능**하다.
피팅 입력을 α로 일원화한 것은 의도적 결정이다: raw→α(보정 물리)와 α→농도(피팅
수학)를 분리하면 결과가 이상할 때 원인이 어느 단계인지 즉시 좁힐 수 있다.

코드도 같은 철학으로 나뉜다 — 물리·수학 코어(`core/`)는 GUI를 전혀 모르고,
GUI(`gui/`)는 코어를 불러 쓰기만 한다. 핵심 수치 루틴은 **단일 구현 원칙**을
따른다: raw 컬럼 배치는 `raw_parser.py` 한 곳, Rayleigh 물리는 `physics.py` 한 곳,
QC 문턱식은 `result_io.py` 한 곳에만 있고 나머지 전부가 그것을 가져다 쓴다. 과거
도구 쪽에 물리 계산 사본이 따로 있다가 한쪽만 고쳐져 R이 틀어진 사고를 겪은 뒤
확립한 원칙이다.

## 4. 물리 모델 — 빛의 기록을 흡광계수로

### 4.1 BBCEAS 흡광계수 식

**개념부터.** 우리가 최종적으로 원하는 것은 흡광계수 α(λ) — "이 공기가 파장 λ의
빛을 단위 길이당 얼마나 깎는가"이다. 이것만 구하면 그 다음은 지문 분리(§5) 문제가
된다. BBCEAS에서 α는 "깨끗한 공기 대비 지금 공기가 빛을 얼마나 더 깎았나"
(I_ZA/I − 1)에서 출발해, 경로 길이 정보(거울 반사율 R)와 공기 자체의 산란
(Rayleigh)을 반영해 계산한다:

$$\alpha(\lambda) = R_L\left[\frac{1-R(\lambda)}{d} + \alpha_{Ray}^{ZA}(\lambda)\right]\left(\frac{I_{ZA}(\lambda)}{I(\lambda)} - 1\right) - \left[\alpha_{Ray}^{sample}(\lambda) - \alpha_{Ray}^{ZA}(\lambda)\right]$$

항별로 읽으면:

| 항 | 뜻 |
|---|---|
| $I_{ZA}/I - 1$ | 깨끗한 공기일 때보다 빛이 얼마나 더 깎였나 (측정의 핵심 신호) |
| $(1-R)/d$ | 거울에서 새는 빛의 비율 ÷ 캐비티 길이 = 경로 길이의 역수 스케일 |
| $\alpha_{Ray}^{ZA}$ | 기준(제로에어) 상태의 Rayleigh 산란 |
| $R_L$ | 거울 앞 퍼지 가스 구간 때문에 실제 시료가 채운 길이가 캐비티보다 짧은 것의 보정 (채널별 실측: CH1 0.9330 / CH2 0.9950 / CH3 0.9968) |
| 마지막 대괄호 | 시료 공기와 기준 공기의 온도·압력이 달라 생기는 Rayleigh 차이를 행별 실측 T/P로 빼 줌 |

기존 MATLAB과 동일한 식이며, 구현 검증 과정에서 $R_L$이 괄호 **전체에** 곱해지는
위치까지 원본과 대조해 교정했다(과거 구현은 수식 정리 과정에서 $R_L$이 소거되는
형태였음을 수치 실험으로 확인한 뒤 수정).

### 4.2 Rayleigh 산란 — 하늘이 파란 이유를 정확히 빼기

**개념부터.** 공기 분자는 기체 "흡수"가 없어도 빛을 사방으로 흩뜨려 빼앗는다.
파란빛일수록 심하게(∝1/λ⁴) — 하늘이 파란 이유다. 이 산란은 스펙트럼에서 완만한
기울기로 나타나 흡수와 섞이므로, 계산으로 정확히 알아내서 빼야 한다. 얼마나
산란하는지는 물리학이 잘 아는 문제라서, 굴절률의 파장 의존(분산식)에서 유도된다.

기존 MATLAB은 측정에 맞춰 계수를 피팅한 **경험식**을 썼다. CAESAR Pro는 **문헌
분산식(Sellmeier)** 을 쓴다: N₂ = Peck & Reeder (1972), O₂ = Bates (1984),
He = Cuthbertson (1936), 분자 비등방성 보정(King factor, Bodhaine et al. 1999)
포함. 경험식은 그 측정 조건 밖에서 신뢰를 보장하지 못하지만, 분산식은 물리 상수라
어디서나 같고 **문헌 골든값과 자동 대조**할 수 있다 — 실제로 447 nm에서 문헌값과
0.000% 일치함을 검증기가 상시 확인한다. 경험식과의 차이는 −3.2%로 정량화해 두었다
(분산식이 문헌과 일치하므로 차이의 출처는 경험식 쪽).

σ(산란 단면적, 분자 1개의 고유값)와 α(단위 길이당 감쇠)를 명확히 구분해
α = σ·N(T,P)로 환산한다 — 온도·압력이 바뀌면 분자 수밀도 N만 바뀌고 σ는 그대로
이므로, σ는 파장 함수로 한 번만 계산하고 행마다 스칼라 N만 곱한다(속도 이득도 큼).
구현 과정에서 King factor의 ν² 항이 ν로 들어간 오류와 O₂ 상수 오타(1.09→1.096)를
발견·교정했다 — 각각 σ에 ~0.15%, ~0.5%의 **계통편향**(전 데이터가 같은 방향으로
틀리는 오차)을 만들던 항목이다. 무작위 오차는 평균하면 줄지만 계통편향은 아무리
평균해도 남는다. 그래서 이런 항목이 노이즈보다 무섭다.

### 4.3 거울 반사율 — 단일값이 아니라 시계열 R(t)

**개념부터.** R은 어떻게 잴까? 직접 잴 수는 없고, **산란량이 잘 알려진 두 기체를
넣어 보고 밝기 차이로 역산**한다. 헬륨은 빛을 거의 산란하지 않고(밝음), 제로에어는
질소·산소만큼 산란한다(어두움). 같은 캐비티에서 이 밝기비 r = I_ZA/I_He는 순전히
"알려진 산란 차이 × 경로 길이"의 결과이므로, 여기서 경로 길이, 즉 (1−R)/d가 나온다
(Washenfelder et al. 2008):

$$\frac{1-R}{d} = R_L\,\frac{r\,\alpha_{Ray}^{ZA} - \alpha_{Ray}^{He}}{1 - r}, \qquad r = \frac{I_{ZA}}{I_{He}}$$

장비는 몇 시간마다 He/ZA를 자동 주입하므로 R을 하루에도 여러 번 얻을 수 있다.
문제는 **모든 주입이 성공하지는 않는다**는 것 — 가스가 캐비티를 다 채우기 전의
스펙트럼이 섞이거나, 주입 자체가 불량이면 엉터리 R이 나온다. CAESAR Pro는 개별
주입을 물리 기반 게이트 세 개로 거른다:

- **주입 플래그 엄격 구분** — 장비가 기록하는 상태 플래그 중 "주입 완료" 상태
  (500=ZA, 510=He)만 채택. 밸브 전환·대기 구간(501–503, 511–513)은 캐비티가
  아직 안 채워진 상태라 배제.
- **He/ZA 밝기 대비(contrast) 검사** — 정상 사이클의 (I_He−I_ZA)/I_He는
  0.17–0.21로 실측된다. 0.05–0.35 밖이면 주입 불량(가스 안 나옴, He/ZA 역전)
  으로 보고 그 사이클 전체를 제외.
- **비물리 R 검출은 자르기(clip) 전에** — 계산상 R이 1을 넘으면 비물리이므로
  걸러야 하는데, 과거 구현은 R을 1.0으로 잘라낸 **뒤에** 검사해서 비물리
  사이클이 R=1.000으로 "위장"된 채 통과했다. 지금은 자르기 전 값으로 판정한다.

게이트를 통과한 주입쌍들은 시간축 위의 점(knot)이 되고, 그 사이를 **PCHIP으로
보간해 연속 함수 R(t)** 를 만든다. PCHIP은 점들을 부드럽게 잇되 점 밖으로
튀어나가지 않는(오버슈트 없는) 보간법이라, 물리량이 "측정된 범위를 벗어나는 값으로
보간되는" 일이 없다. 종전 방식(측정 런 전체에 단일 R)은 런 경계마다 경로 길이가
계단식으로 점프했고 R의 하루 변화 정보를 버렸다.

같은 논리로 **I₀도 시계열 I₀(t)** 다: 개별 ZA 스캔은 ~1% 노이즈가 있으므로 주입
블록 단위로 평균해 노이즈를 죽인 점들을 만들고, 그 사이를 PCHIP 보간해 LED
드리프트를 따라간다.

### 4.4 시각과 환경 변수 — 사소해 보이지만 틀리면 다 틀리는 것들

- **행별 시각**은 LabVIEW가 심어 둔 2컬럼 정수를 `(col0<<16)|col1`로 합쳐 "연초
  기준 센티초"로 직접 읽는다. 기준 자료(박사님 .mat의 날짜시각)와 표준편차
  0.0000초로 일치함을 검증했다. 행 간격을 "약 0.97초"라는 상수로 합성하는 방식은
  주입·공백 구간을 건너뛴 시간을 놓치므로 쓰지 않는다.
- **온도·압력**은 행별 하우스키핑 실측값이다. LabVIEW 기록이 중단되며 꼬리가
  잘린 파일(캠페인 중 실제로 다수 발생)도 컬럼 시프트 추론 + 압력 타당성 검사
  (800–1200 mbar)로 T/P를 복구하며, 복구가 안 되면 몇 행이 기본값으로 대체됐는지
  **경고로 보고**한다(조용한 대체 금지).
- 열분해 채널(180/300 °C로 가열해 PAN류를 NO₂로 분해해 재는 채널)의 농도 환산에는
  히터 설정값(75 °C)이 아니라 **셀 내부 실측 온도**(CH1≈34 °C)를 쓴다. 이상기체
  법칙으로 ppb를 환산할 때 온도가 틀리면 그대로 계통오차가 되기 때문이다.

## 5. DOAS 피팅 — 겹친 지문을 분리해 농도로

### 5.1 모델: 측정된 α는 무엇의 합인가

**개념부터.** §4가 끝나면 파장별 흡광계수 α(λ)가 있다. 이 안에는 여러 기체의
지문이 **겹쳐서** 들어 있고, 그 밑에 완만한 배경(광학계 특성, 남은 산란 등)이
깔려 있다. 피팅이란 "α(λ) = 각 기체 지문 × 농도의 합 + 완만한 배경 + 간섭무늬"
라는 모델을 세우고, 측정과 가장 잘 맞는 농도 조합을 찾는 최소제곱 문제다:

$$\alpha(\lambda) = \sum_i c_i\,\sigma_i\big(\lambda;\,s_i,\,q_i\big) + \sum_{j=0}^{P} p_j\,T_j(x) + a\sin(f\lambda) + b\cos(f\lambda)$$

- $c_i$ = 기체 i의 농도(우리가 찾는 답). $\sigma_i$ = 문헌에서 가져온 기체 i의
  지문(흡수 단면적 스펙트럼).
- $s_i, q_i$ = shift·squeeze. 분광기의 파장 눈금은 온도에 따라 미세하게 밀리고
  (shift) 늘어난다(squeeze). 지문을 측정 눈금에 맞춰 살짝 이동·신축시키는
  파라미터다.
- $T_j$ = Chebyshev 다항식 = 완만한 배경. (그냥 1, x, x², …를 쓰면 고차에서
  수치적으로 서로 닮아 계산이 불안정해진다. Chebyshev는 서로 최대한 다르게 생긴
  다항식 집합이라 안정적이다. 핏 구간을 [−1,1]로 사상해 사용.)
- $a\sin + b\cos$ = etalon 간섭무늬(아래 §5.4).

### 5.2 왜 Variable Projection인가

이 모델의 미지수는 성질이 두 부류다: 농도·배경 계수($c_i, p_j, a, b$)는 **선형**
(모델에 1차로 들어감 → 답이 공식 한 방에 나옴), shift/squeeze($s_i, q_i$)는
**비선형**(반복 탐색이 필요함). 전부를 한 덩어리로 비선형 탐색기에 넣으면 탐색
공간이 커져 느리고 지역해에 빠지기 쉽다.

**Variable Projection(VarPro)** 은 이 구조를 이용한다: 비선형 탐색은
shift/squeeze에 대해서만 하고, 탐색기가 shift/squeeze 후보를 하나 내놓을 때마다
그에 대한 **최적 선형 계수는 해석적으로(공식으로) 즉시** 구해 버린다. 탐색 공간이
수십 차원 → 수 차원으로 줄고, 선형부는 항상 전역 최적이 보장된다. 선형 단계에는
옵션이 셋 있다:

- **±Neg (음수 허용, 기본 ON)** — §5.5에서 따로 설명.
- **Tikhonov 정칙화** — 계수 폭주를 누르는 안전장치. 단, 배경 다항식 열은 누르지
  않는다(배경을 누르면 그 몫이 기체 계수로 새어 농도가 편향된다).
- **Robust IRLS(Tukey biweight)** — 우주선 히트 같은 한두 픽셀 스파이크의 영향을
  자동으로 줄이는 반복 가중(옵션).

### 5.3 Shift/Squeeze 운용 — 자유와 통제 사이

shift를 완전히 풀어 두면 노이즈가 심한 스캔에서 지문이 엉뚱한 곳에 "가서 붙는"
폭주가 일어나고, 완전히 고정하면 실제 열드리프트를 못 따라간다. CAESAR Pro는
기체마다 **Limit(구간 제한) / Fix(절대값 고정) / Free / Link(다른 기체에 연동)**
4모드를 지정할 수 있고, 여기에 **스캔 간 step limit**(직전 스캔 대비 프레임당 최대
0.5 px)을 결합했다 — 열드리프트는 느리게 흐르는 물리량이므로 "천천히 변하는 것은
따라가되 한 스캔이 갑자기 튀는 것은 막는" 규칙이다. 콜드 채널처럼 개별 스캔의
신호가 약해 스캔 하나로는 shift를 정할 수 없는 경우, Fix 0 + 시간축 이어받기
(직전 유효 shift에서 출발) 전략을 쓴다. 이는 캠페인 데이터로 확인한 운영 규칙이다.

### 5.4 Etalon 간섭무늬 — 비선형 문제를 선형으로 바꾼 트릭

광학 부품의 얇은 층(코팅, 창)에서 빛이 자기 자신과 간섭하면 스펙트럼에 규칙적
물결무늬(etalon fringe)가 생긴다. 이걸 모델에 안 넣으면 그 물결이 기체 농도로
오인된다. 물결은 A·sin(fλ+φ)인데 진폭 A와 위상 φ가 미지수면 비선형 문제다.
삼각함수 항등식 A·sin(fλ+φ) = a·sin(fλ) + b·cos(fλ)를 쓰면 **주파수 f만 알면
나머지는 선형**이 된다. 그래서 f는 잔차의 FFT(주파수 분석)로 하루 한 번 검출하고
(광학 구조에서 오는 값이라 일중 안정), sin·cos 두 열을 선형부에 넣는다 — 같은
모델을 유지하면서 전역해가 보장되는 형태로 바꾼 것이다.

### 5.5 음수 농도를 왜 허용하는가 (±Neg, 기본 ON)

농도는 물리적으로 음수일 수 없으니 피팅에서 음수를 금지(하한 0)하는 게 옳아
보인다. 그러나 통계적으로는 반대다. 참농도가 0에 가까운 기체는 노이즈 때문에 핏
결과가 0 주변을 **대칭으로** 오르내린다. 음수를 금지하면 그 아래쪽 절반이 0으로
잘려 올라오고, 평균이 항상 양수로 뜬다(정류 편향, rectification). 검출한계 근처
농도와 PNs = CH1−CH2 같은 **차분량**이 특히 심하게 왜곡된다. 그래서 기본값은 음수
허용이다 — 개별 음수값은 오류가 아니라 노이즈의 절반이고, 평균에서 상쇄된다.
어느 쪽을 썼는지는 결과 파일 헤더와 저장 폴더 이름(neg_o/neg_x)에 항상 기록된다.
(참고로 기존 DOASIS도 비제약 선형핏이라 음수를 허용한다 — 철학이 같고, CAESAR
Pro는 그것을 명시적 선택지로 노출한 것.)

### 5.6 품질지표와 오차 — 숫자마다 신뢰도를 달아서

행마다 잔차 RMS, reduced χ², 자유도, SNR을 함께 출력한다. reduced χ²("핏이
노이즈 수준만큼 맞았나"의 지표)를 계산하려면 픽셀 노이즈 σ를 알아야 하는데, 이를
스펙트럼 자체에서 **이웃 픽셀 차분의 표준편차 ÷ √2**(von Neumann 추정)로 구한다 —
완만한 실제 구조는 이웃 차분에서 소거되고 픽셀 노이즈만 남는 성질을 이용한 것이라,
"신호를 노이즈로 오인"하지 않는다. 농도 오차는 선형해의 공분산에서 전파하고, ppb
환산에 쓰인 온도·압력의 불확도(±1 °C, ±1 mbar)까지 합성한 total error와
검출한계(MDL = 3σ)를 함께 기록한다. 스무딩(Kalman)한 값은 **별도 _Smooth 컬럼**
으로만 나간다 — 주 컬럼은 항상 날것의 핏 결과다("화장한 데이터는 민낯과 같이
제출한다"는 원칙).

### 5.7 병렬화 — 빠르게, 단 결과가 같음을 증명한 뒤에

수십만 스캔 피팅은 단일 코어로 수 시간이 걸린다. 병렬화의 장애물은 §5.3의 시간축
이어받기다 — 스캔들이 앞 스캔의 shift에 의존하면 마음대로 쪼갤 수 없다. 다행히
α 입력 경로에서 스캔 간에 이어지는 상태는 **직전 유효 shift 하나뿐**임을 확인했고,
그래서 연속 스캔을 청크로 나누되 각 청크 앞에 40스캔 "워밍업"을 붙여 shift를
재정착시킨 뒤 본체를 피팅하는 방식을 썼다. 채택 기준은 속도가 아니라 동일성이었다:
**실제 콜드 캠페인 데이터로 순차 처리와 스캔별 대조해 ~10⁻⁶ ppb 수준(부동소수점
잡음 수준)으로 일치**함을 확인한 뒤에야 기본 모드로 채택했다. 수치 라이브러리
(BLAS) 스레드를 워커당 1개로 제한해 과구독을 막고, 총 프로세스 예산(논리 코어의
절반)을 채널 수로 나눠 다채널 동시 피팅에서도 부하가 일정하다. α 생성 쪽도 병목인
파싱만 병렬화했고, 순차 경로와 **출력 바이트가 동일**함을 검증했다.

## 6. 데이터 무결성과 QC — 지우지 말고 표시하라

자동 품질관리(QC)는 다음 다섯 장치로 구성된다. 공통 철학은 §2의 "비파괴"다.

1. **비파괴 플래그** — QC로 제외된 행은 농도가 NaN이 되고 Status 열에 사유가
   문자열로 남는다(`QC-Auto (rms=…)`, `Settling` 등). 원본 농도는 내부에 백업되어
   있어, QC 파라미터를 바꿔 **재피팅 없이** 몇 번이고 다시 적용해 볼 수 있다.
2. **분포 기반 문턱** — "RMS가 얼마 이상이면 나쁜 스캔인가"의 문턱을 사람이 정하지
   않는다. 그날 데이터의 RMS 분포에서 중앙값(median)과 MAD(중앙값 절대편차 —
   표준편차의 강건한 대체물로, 이상치가 섞여도 오염되지 않음)를 구해
   thr = 10^(median + K·MAD)로 자동 유도한다(log₁₀ 공간을 쓰는 이유는 RMS 분포가
   한쪽으로 길게 치우쳐 있어 로그에서 대칭이 되기 때문). 사람이 정하는 것은 감도
   K 하나뿐이고, 같은 식 하나를 핏 직후 QC·Result Lab·내보내기가 공유한다.
3. **물리 사유 우선** — 통계 문턱과 별개로 물리적 근거가 있는 제외가 먼저다:
   구름·저광량 스캔(그날 분포 기준으로는 정상처럼 보여 절대 RMS 상한으로만 잡힘),
   SNR 하한, 그리고 **정착(settling) 스캔** — He/ZA 주입에서 대기 측정으로 복귀한
   직후 캐비티에 바깥 공기가 덜 채워진 각 사이클 첫 ~3빈은 농도가 낮게 나온다
   (실측 −16% 편향 확인 후 도입). 어떤 사유로 빠졌는지가 전부 Status에 남는다.
4. **입력 오염 방어** — α 생성 입력은 측정 파일명 규칙(`YYYY-MM-DD-NNN`)
   화이트리스트로 거른다. raw 폴더에 섞여 있던 분석 산출물 .dat 파일 하나가
   스캔으로 오인 파싱되어 한 달치 α를 오염시킨 실제 사고(2026-07-09 규명) 후
   도입한 방어다.
5. **재현성 기록** — 모든 결과 파일 상단 # 헤더에 코드 버전(git 해시), 핏 구간,
   다항식 차수, 정칙화 λ, Robust, ±Neg, QC 세팅, 보정 이력(R 출처, I₀ 모드,
   dark/offset/stray)이 기록된다. 저장은 날짜/±Neg/QC별 폴더로 자동 분류되고,
   같은 세팅으로 재피팅하면 기존 파일은 삭제되지 않고 시각이 붙어 `_archive/`로
   보존된다.

## 7. 검증 — 이 프로그램의 결과를 왜 믿을 수 있나

"믿음"이 아니라 재검증 가능한 기록으로 답한다. 세 겹이다.

**① 기존 파이프라인과의 단계별 수치 대조** (한 번 수행, 스크립트·결과 보존):

| 단계 | 대조 방법 | 결과 |
|---|---|---|
| raw 파싱 | Python vs MATLAB 추출 바이트 비교 | 완전 일치 |
| 행별 시각 | bytepack vs 기준 .mat doy | 표준편차 0.0000 s |
| Rayleigh | σ_ZA@447nm vs 문헌 골든값 | 0.000% 이내 |
| α 생성 | 동일 시간 MATLAB α와 대조 | 일치 (diagnostics에 보존) |
| 병렬 피팅 | 순차 결과와 스캔별 대조 | ~10⁻⁶ ppb |
| α 병렬 파싱 | 순차 경로와 출력 비교 | 바이트 동일 |

**② 상시 회귀 검증기** — 연구 코드는 수정이 잦고, "여길 고쳤더니 저기가 깨지는"
사고가 가장 흔하다. 코드 수정 후와 릴리즈 전에 반드시 돌리는 자동 검사 2종을 상시
운용한다: `validate_pipeline.py`(파싱 바이트 대조, 파장보정 Hg 램프 기준선
±0.07 nm, 레퍼런스 처리, Rayleigh 골든값, R·경로 물리성, 핏 출력 타당성 — 6항목
PASS/FAIL)와 `validate_plotmaker.py`(시각화 24항목 — 미리보기와 출판 출력이 같은
그림을 그리는지, 일부러 버그를 심으면 실제로 FAIL이 뜨는지까지 확인한 스위트).

**③ 결과 자체의 provenance** — §6-5의 헤더 기록 덕에, 몇 달 뒤 어떤 결과 파일을
집어도 "어느 코드 버전이 어떤 세팅으로 만든 것인지"를 복원할 수 있다.

남은 검증 항목도 명시한다: **피팅 단계의 DOASIS 직접 교차 대조**(같은 α를 DOASIS와
CAESAR Pro 양쪽에서 핏해 NO₂ 시계열 비교)는 아직 수행 전이다. 내보내기 형식을
DOASIS 호환으로 유지해 둔 것이 이 대조의 통로다(§9.2).

## 8. 워크플로와 편의 기능

### 8.1 채널 탭과 시나리오

좌측 패널의 채널 탭은 채널마다 독립 세팅(레퍼런스 세트, 파장보정, 핏 구간, 다항식
차수, 시간 시프트, 가스온도)을 보유하고, RUN 시 채널별 워커가 병렬로 돈다. 전
채널 세팅은 시나리오 JSON 하나로 저장/복원된다 — 예컨대 "Cold 775–1550px / 4차 /
NO₂·CHOCHO·H₂O"라는 박사님 세팅을 클릭 한 번에 그대로 재현한다.

### 8.2 사고 예방 장치

밤샘 배치 처리에서 가장 비싼 사고는 "잘못된 세팅으로 다 돌린 뒤 아침에 발견"이다.

- **RUN 확인 다이얼로그** — 실행 직전 채널별 파장보정 파일명·핏 구간·레퍼런스·
  시프트·가스온도를 한 화면에 요약해 확인받는다.
- **Test Fit(1스캔)** — 본 실행 전에 첫 스캔 하나만 즉석 피팅해 측정+모델 겹침,
  잔차, 농도, shift를 팝업으로 보여준다. 세팅 오류를 10초 만에 잡는 용도.
- **파장보정 상시 표시** — 현재 로드된 wavecal 파일명이 패널에 항상 보인다
  (안 보여서 구버전으로 돌린 사고 재발 방지).
- **레퍼런스 Lock** — 레퍼런스 변경은 명시적 Lock으로만 엔진에 반영되고, Lock
  없이 RUN하면 경고한다.
- **크래시 대비 자동저장** — 결과가 나올 때마다 즉시 파일에 덧붙여, 밤샘 런이
  중간에 죽어도 그때까지의 결과가 남는다.

### 8.3 Result Lab / Plot Maker / R Calibrator

- **Result Lab** — 저장된 모든 산출물(R 트렌드, R 커브, α, 레퍼런스, 농도)을 형식
  자동 인식으로 열람. 기간 자르기/병합, QC 사후 재적용, 다단계 수식 계산기
  ((A−B)/C 등, 시간축 자동 정렬), 핏 행 클릭 → 해당 α 스펙트럼 팝업 추적.
- **Plot Maker** — 여러 결과를 올려 시계열/산점도/일변화(diurnal)/Allan 그림 합성.
  미리보기(pyqtgraph)와 출판 출력(matplotlib)의 동작 일치를 검증기로 보장, 종별
  일괄 출력(Batch Publish), 그림 규약 프리셋(데이터 공백은 마커만, x축 양끝 tight,
  종별 색 통일).
- **R Calibrator** — 좌패널 세팅을 상속해 채널별 R 시계열을 계산·저장. 이미 계산된
  날은 재스캔 없이 증분 갱신, 빈 날 검증, α 생성용 R(t) 파일 내보내기.
- **날짜 로더** — 기간을 고르면 일별 파일을 자동 병합(캐시·무효화 처리)하는 공용
  다이얼로그.

### 8.4 성능

| 항목 | 개선 |
|---|---|
| 100 MB×1200파일 인덱싱 | 행수 디스크 캐시: 첫 1회 이후 0초 (도입 전 ~7시간) |
| α 생성 파싱 | 멀티프로세스(코어 절반), 순차와 바이트 동일 검증 |
| α 생성 메모리 | 디스크 스트리밍으로 수 GB RAM 버퍼링 제거 |
| DOAS 피팅 | 청크+워밍업 멀티프로세스(§5.7), GUI 응답성 유지 |
| Rayleigh σ | 파장 함수로 1회 계산 후 스칼라 N(T,P)만 곱함 |

## 9. 기존 워크플로(MATLAB + DOASIS) 대비 차별점

기존 워크플로는 2단이었다: **MATLAB 스크립트**(박사님 작성)가 raw → α·R을 만들고,
그 α를 bin당 1파일로 내보내 **DOASIS**(하이델베르크대의 표준 DOAS 피팅 소프트웨어)
에서 피팅한 뒤 결과를 다시 수집했다. CAESAR Pro는 두 단을 모두 대체하므로 비교도
두 축으로 나눈다.

### 9.1 전처리(α·R 생성) — vs MATLAB

| 측면 | MATLAB 파이프라인 | CAESAR Pro |
|---|---|---|
| R | 런/일 단위 단일값에 가깝게 운용 | 주입쌍별 점 → PCHIP **R(t)** 시간보간 + 물리 게이트로 불량 주입 자동 배제 |
| I₀ | 블록 평균 | ZA 블록평균의 **PCHIP I₀(t)** (LED 드리프트 추적) |
| Rayleigh | 경험식(피팅 계수) | 문헌 분산식 + King 보정, 골든값 자동 검증 |
| 처리 속도 | 단일 스레드 | 파싱 멀티프로세스(순차와 바이트 동일 검증) |

### 9.2 스펙트럼 피팅 — vs DOASIS

| 측면 | DOASIS | CAESAR Pro |
|---|---|---|
| 도메인 | 범용 DOAS(광학밀도) — CEAS 변환은 외부에서 끝내고 들어옴 | BBCEAS 특화 — α 도메인에서 R(t)·Rayleigh·경로 보정이 피팅과 한 몸 |
| 알고리즘 | Levenberg–Marquardt | **VarPro** — 선형/비선형 분리로 탐색 축소·선형부 전역해 보장, 정칙화·robust 옵션 |
| Shift/Squeeze | 시나리오별 설정, 스캔 간 독립 | 기체별 4모드 + step limit + **시간축 이어받기**(약신호 채널에 필수) |
| Etalon | 기본 미내장(수동 레퍼런스로 추가) | FFT 주파수 검출 + sin/cos 선형화 내장 |
| 음수 처리 | 비제약(음수 허용) | 같은 철학 + **±Neg 명시 토글** + 헤더 기록 |
| 배치 처리 | bin당 1파일 수동 왕복 + 스크립팅 | 폴더 단위 원클릭, 멀티코어(순차와 ~10⁻⁶ ppb 일치 검증) |
| QC | 피팅 후 외부에서 수동 | 분포 기반 자동 + 사유별 비파괴 플래그, 재핏 없는 재적용 |
| 재현성 | 시나리오 파일 관리에 의존 | git 해시+전체 세팅 자동 스탬프, `_archive` 버전 보존 |

호환성은 일부러 남겼다: per-bin 내보내기 형식과 픽셀 단위 핏 구간(예: 775–1550)은
**DOASIS가 그대로 읽고 재현할 수 있는 형태**로, 두 프로그램 교차검증의 통로다.

### 9.3 운영 전반

| 측면 | MATLAB + DOASIS | CAESAR Pro |
|---|---|---|
| 파이프라인 | 프로그램 2개 사이 파일 수동 왕복 | 단일 GUI에서 raw → α → 핏 → 그림 |
| 검증 | 1회성 | 상시 회귀 검증기 2종 |
| 접근성 | 스크립트·시나리오 편집 필요 | GUI + 시나리오 JSON + 사고 예방 장치 |

## 10. 한계와 향후 (Discussion)

솔직한 한계와, 거기서 도출되는 다음 단계를 명시한다. 방향을 한 줄로 요약하면
**"농도를 내는 소프트웨어"에서 "불확도를 말할 수 있는 소프트웨어"로**다.

1. **콜드 채널 잔차의 고정 패턴** — 콜드 잔차에 스캔마다 반복되는 고정 구조가
   커서 NO₂ 불확도가 노이즈가 아니라 잔차 구조에 의해 제한된다. H₂O/O₄ 레퍼런스
   보강과, 고정패턴 성분을 핏 기저에 직접 넣는 실험(기반 코드는 구현되어 있으나
   미연결)이 다음 단계다.
2. **오차 예산의 체계화** — 현재 오차는 핏 공분산 + 온압 전파까지다. σ(R), 캐비티
   길이, 단면 문헌 불확도까지 합친 계통오차 예산의 자동 보고는 미구현이다. Allan
   편차 기반 검출한계 산출 자동화와 함께 논문 Table의 직접 재료가 되는 항목.
3. **DOASIS 교차 피팅** — §7 말미의 남은 검증. 같은 α를 양쪽에서 핏해 NO₂를
   대조하면 정확도 검증과 기존 워크플로와의 연속성 입증이 한 번에 된다.
4. **Hot 채널 스케일** — CH1/CH2 스케일 슬로프가 광학 얼라인먼트 상태와 강상관
   (r≈+0.76)임을 확인했으나, ANs의 실제/열적 성분 분리와 기간별 보정 적용 여부는
   미결이다.
5. **레거시 경로 정리** — raw 직접 피팅 경로는 보존돼 있으나 현 워크플로에서
   차단 상태이고, 그 안의 Temporal I₀ 보간은 인덱스 기준이 구식이다(도달 불가
   경로지만 정리 대상).
6. **배포 패키징·지속가능성** — **완료(2026-07-16)**. 경로 이식성·버전 태깅
   (v0.2.0)에 더해: ① requirements 버전 고정(깨끗한 venv 설치→임포트 스모크
   63 OK로 검증), ② GitHub Actions CI — 커밋마다 전 모듈 임포트 스모크 +
   `validate_pipeline --no-data`(Rayleigh 골든값) + 계단가드·공선성 단위테스트 +
   validate_plotmaker(offscreen 24항목), 첫 실행 green 확인, ③ 운용자 조작
   매뉴얼 `docs/매뉴얼_조작순서.md`(R 캘리브→α→핏→QC→출판 전 과정).
   남은 여유 항목: HITRAN 오프라인 번들.
7. **R(t)/I₀(t) 계단 변화 가드** — **완료(2026-07-16)**. PCHIP 보간이 계단형
   변화(거울 청소·재정렬·급오염)를 램프로 뭉개는 문제를 `core/step_guard.py`로
   해결: 계단 점수 min(인접쌍 변화율, 5-knot 중앙값 지속 변화율)이 적응 문턱
   max(0.15, 2×p95)을 넘으면 보간을 분절하고(knot 삭제 없음), 운영자가 아는
   이벤트는 R Calibrator "R(t) Breaks…"로 수동 분절한다. 감지 결과는 R
   Calibrator·α 생성 로그에 항상 경고로 보고. 문턱 산정 근거·실측 영향
   (CH1 0.157% 구간만 변화, CH2/콜드 0.000%)은
   `docs/step_guard_threshold_2026-07.md` 참조.
8. **Etalon–기체 공선성 진단** — **완료(2026-07-16)**. differential 공간
   (poly 사영 제거 후) 기체↔etalon 부분공간 다중상관 r + VIF를
   `core/doas_fit.py etalon_collinearity()`로 계산, Test Fit 팝업 한 줄과
   결과 파일 `# Etalon-Gas Collinearity` 헤더에 보고(|r|>0.5 경고 —
   핏 결과는 바꾸지 않음). 캠페인 콜드 시나리오 실측: 실제 etalon 주파수
   (5.4 px 주기)에서 세 기체 모두 r≈0.000·팽창 ×1.00, 검출 밴드 전체 최악
   r=0.15(문턱의 30%) — `docs/etalon_collinearity_2026-07.md` 참조.

6·7·8은 완료됐다(각 항목의 근거 문서 참조). 원 실행 계획은
`docs/개선작업지시_2026-07.md`.

## 부록 C. 용어 사전 (가나다·알파벳순)

| 용어 | 뜻 |
|---|---|
| 계통오차 | 전 데이터가 같은 방향으로 틀리는 오차. 평균해도 사라지지 않아 무작위 오차보다 위험 |
| 리트리벌(retrieval) | 측정된 신호에서 원하는 물리량(여기서는 농도)을 역산하는 과정 |
| 정류 편향(rectification) | 0 주변 노이즈의 음수 절반을 잘라내면 평균이 위로 뜨는 통계 편향 (§5.5) |
| 주입(injection) | 교정용 가스(He 또는 ZA)를 캐비티에 흘려 넣는 자동 절차 |
| 지문(단면적, cross-section) | 기체가 파장별로 빛을 얼마나 흡수하는지의 고유 곡선. 문헌 실측값을 사용 |
| 캐비티(cavity) | 고반사율 거울 두 장이 마주 보는 광학 구조. 빛을 가둬 경로를 증폭 |
| BBCEAS | Broadband Cavity-Enhanced Absorption Spectroscopy — LED 광원 + 캐비티 흡수분광 |
| Chebyshev 다항식 | 수치적으로 안정한 다항식 집합. 완만한 배경을 표현 (§5.1) |
| DOAS | Differential Optical Absorption Spectroscopy — 겹친 흡수 지문을 분리하는 피팅 기법 |
| DOASIS | 하이델베르크대의 표준 DOAS 피팅 소프트웨어. 기존 워크플로의 피팅 담당 |
| etalon fringe | 광학 부품 얇은 층의 간섭으로 생기는 규칙적 물결무늬 (§5.4) |
| HK(하우스키핑) | 스펙트럼 외의 보조 기록 — 온도, 압력, 주입 상태 플래그, 시각 |
| I₀ | 기체가 없을 때(제로에어)의 기준 밝기 스펙트럼 |
| MAD | 중앙값 절대편차. 이상치에 오염되지 않는 표준편차 대체물 (§6-2) |
| MDL | 검출한계(Method Detection Limit). 여기서는 3σ 기준 |
| PCHIP | 점 사이를 부드럽게 잇되 점 밖으로 튀지 않는(오버슈트 없는) 보간법 |
| ppb / ppt | 10억분율 / 1조분율. 공기 분자 대비 대상 분자의 개수 비 |
| provenance | 산출물이 "어떤 코드·세팅으로 만들어졌나"의 이력. 결과 헤더에 자동 기록 |
| R | 거울 반사율. 유효 경로 길이를 결정하며 시간에 따라 변함 (§4.3) |
| R_L | 거울 앞 퍼지 구간 때문에 시료가 실제로 채운 길이 비율의 보정 계수 |
| Rayleigh 산란 | 공기 분자 자체의 빛 산란(하늘이 파란 이유). 흡수처럼 보여 빼야 함 (§4.2) |
| RMS(잔차) | 핏과 측정의 차이(잔차)의 제곱평균제곱근. 핏 품질의 기본 지표 |
| shift / squeeze | 분광기 파장 눈금의 밀림/신축. 온도에 따라 서서히 변함 (§5.3) |

| von Neumann 추정 | 이웃 픽셀 차분으로 노이즈만 골라 추정하는 방법 (§5.6) |
| ZA(제로에어) | 측정 대상 기체가 제거된 깨끗한 공기. I₀와 R 교정에 사용 |
