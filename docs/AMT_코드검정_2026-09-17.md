## 2. A7 — `STEP_LIMITED` 신설 🔴 (`ef2a935`, `fa0a6d1`)

### 문제

`setup_fit_parameters`는 두 경계의 **교집합**을 solver 상자로 준다.

```python
window_lb, window_ub = anchor - step_limit, anchor + step_limit
sh_lb, sh_ub = max(global_lb, window_lb), min(global_ub, window_ub)
```

`least_squares`는 그 상자 **안에서** 수렴하므로, 최적점이 상자 밖이면 경계에 붙은 채
성공 코드(1~4)를 돌려준다. `_aggregate_solver_termination`은 음수도 0도 아니면 전부
`CONVERGED`로 분류했다 → **보폭 제한 때문에 못 움직인 핏이 수렴으로 기록됐다.**

`res.optimality`로는 못 잡는다. 경계에서 scipy가 보는 건 **투영** gradient라,
진짜 gradient가 0이 아니어도 0으로 나온다. 경계 근접을 직접 재는 수밖에 없다.

### 구현

1. `setup_fit_parameters(..., return_bounds=True)` → 7번째 원소 `bounds_meta`에
   `global_lb/global_ub/window_lb/window_ub/degenerate`를 `active_vars`와 같은 순서로.
   **기본값 `False`라 기존 6-튜플 호출부(15곳 + 테스트 더블 3개)는 한 줄도 안 건드렸다.**
   사양서는 "필드 추가"라고 했지만 7-튜플로 바꾸면 공통규칙 2번(기존 테스트 유지)을
   깨므로 명시 인자로 갔다(작성자 동의).
2. `classify_theta_bounds()` — 상자 안=`CONVERGED`, global 경계=`AT_BOUND`,
   window 경계만=`STEP_LIMITED`. 둘 다면 `AT_BOUND`(보폭을 풀어도 허용범위가 막는다).
3. 허용오차는 **상대값** `BOUND_REL_TOL = 0.02`(상자 폭 대비). shift는 px(폭 ~1),
   squeeze는 무차원(폭 ~0.01)이라 절대 허용오차를 공유할 수 없다. 0.02는
   `core.fit_optimizer.fit_window`의 `shift_at_bound`가 이미 쓰던 값이다 —
   두 곳이 다른 문턱을 쓰면 같은 핏을 한쪽은 경계라 하고 한쪽은 아니라 한다.
4. 우선순위 `FAILED > MAX_NFEV > STEP_LIMITED > AT_BOUND > CONVERGED`.
5. `gui/worker.py` 배선: `_setup_fit_parameters`가 `bounds_meta`를 스캔 단위로 들고 있고
   `_execute_varpro_fit`이 `return_diagnostics=True`로 받아 Status 열에 ` · STEP_LIMITED`를
   붙인다 → `run_meta.rows.by_status`에 자동 집계된다. **행은 안 버린다**(무결성 헌장).

### 후속 결함 (`fa0a6d1`) — 실측으로 잡았다

교집합이 **비는** 경로가 있다(예: `sh_val "-9,-1.5"`인데 anchor 0·step 0.5).
그때 `setup_fit_parameters`는 `near` 둘레에 폭 2e-4짜리 구제 상자를 준다. 해는 그
상자 **한가운데** 앉으므로 어떤 경계에도 안 붙고 → 다시 `CONVERGED`가 된다.
실제로는 최적화가 아니라 shift가 매 스캔 같은 값으로 **고정**된 것이다.

실측: 2026-06-14 PNs 알파를 그 정책으로 돌리면 shift가 세 스캔 모두 정확히 −1.5000
(=global_ub)인데 상태는 CONVERGED였다. `bounds_meta`에 `degenerate` 플래그를 싣고,
그 파라미터는 위치와 무관하게 경계 적중으로 센다.

## 3. A9 — 설계행렬 열 정규화 🔴 (`1cb28e9`)

### 전제 정정

사양서의 "cond ≈ 2e19, 가스 열이 특이값 절단으로 사라진다"는 **Augur에는 해당하지 않는다**(§1).
실측 2026-06-14 PNs(창 444.1~470.6nm, 551px, poly3, 4종):

```
cond(A)  정규화 전 1.436e+02  →  후 2.385e+01
```

### 그래도 넣은 이유

`scaling_factors`는 **레퍼런스 전체의 max**로 나눈다. 핏 창 안에서만 보면 그 기체의
피크가 창 밖일 때 열 노름이 작아진다. 열의 2-노름으로 직접 정규화하면 창에 무관하게
균일해지고, 위 실측처럼 조건수가 6배 더 내려간다. 비용은 열 노름 한 번이다.

### 수학적 정당성

열공간이 안 바뀌므로 **잔차·투영·GP 자코비안이 정확히 불변**이다:

```
A' = A S⁻¹,  c' = S c      →  A'c' = A c                    (잔차 동일)
D' = D S⁻¹                 →  P⊥ D'c' = P⊥ D c              (자코비안 1항 동일)
A'⁺ᵀ D'ᵀ r = A⁺ᵀ S·S⁻¹ Dᵀ r = A⁺ᵀ Dᵀ r                      (자코비안 2항 동일)
```

`S`가 θ에 따라 변해도 유지된다(양쪽에서 상쇄). 그래서 GP 식은 그대로 쓰고
2항의 `g`만 `s`로 나눈다. **15개 야코비안 테스트(해석 vs 유한차분)가 이 항등의 게이트다.**

적용 지점: `_solve_qr`(QR 경로) · `objective_varpro`(lsq_linear 경로) · 최종 선형해 ·
공분산. Tikhonov 페널티 행도 **같은 S**로 나눈다(증강행렬 `[A;P]`를 통째로 정규화) →
λ의 의미가 안 바뀐다. 공분산은 `Cov[i,j] = Cov'[i,j]/(s_i·s_j)`로 되돌린다.
하한 0은 `s>0`이라 불변.

## 5. 범위 밖 발견 — `fit_optimizer`가 비선형 탐색을 안 돌리고 있었다 (`5bed234`)

`core/fit_optimizer.fit_window`는 Stage-1 자동 최적화(핏레인지 + poly 차수)의 코어인데,
알파를 그대로 넣었다. 즉 **shift 고정 0에서 창·차수 후보를 비교해 왔다.**
그 함수가 내는 `shift_at_bound` 하드 게이트까지 같이 무의미했다.

같은 식의 사본이 셋이라 하나가 조용히 어긋났다. `core.doas_fit.alpha_fit_scale()`
한 곳으로 모으고 `fit_optimizer`·`param_optimizer`가 그걸 부른다(단일 출처 원칙).
선형 결과(`gco/poly_c/eamp/perr`)는 전부 되돌린다 — 비선형 shift/squeeze는 스케일 무관.

> **이건 A절 밖이고 사양서에 없다.** 핏세팅 자동 최적화로 고른 창·차수가 논문에
> 들어간다면, 그 선택은 이 버그 위에서 나온 것이다. 재검토가 필요하다.

## A-1. `AT_BOUND` 12.8 %는 shift가 아니라 **squeeze**였다 — 본문 정정

shift 허용범위를 넓혀 봤다. 세 경우가 **완전히 동일**하다.

| `sh_val` | `CONVERGED` | `STEP_LIMITED` | `AT_BOUND` | NO2 중앙값 |
|---|---|---|---|---|
| `-5, 5` (운영) | 65.75 % | 21.41 % | 12.85 % | 2.204255962898608 |
| `-10, 10` | 65.75 % | 21.41 % | 12.85 % | 동일 |
| `-20, 20` | 65.75 % | 21.41 % | 12.85 % | 동일 |

이유는 shift가 ±5 근처도 안 가기 때문이다 — **min −3.30 px, max +1.56 px**
(p05 −2.56, p95 −0.88). 경계 적중을 파라미터별로 분해하면:

```
NO2_sh:lower:window  1207     NO2_sq:upper:global   732
NO2_sh:upper:window  1212     NO2_sq:lower:global   353
                                            합 1085  = AT_BOUND 건수와 정확히 일치
```

`AT_BOUND` 1085건은 전부 **squeeze가 `sq_val "-0.005, 0.005"` 끝에 박힌 것**이다
(1.005에 719행, 0.995에 338행). shift 적중은 전부 `window`(보폭) 출처다.

> **본문 §6·§11-2의 "shift 허용범위 ±5 px 끝에 박혔다 / 허용범위 설정을 다시 봐야
> 한다"는 틀렸다.** 좁은 것은 shift 범위가 아니라 **squeeze 범위 ±0.005**다.
> 리뷰어가 제안한 "−10,10으로 넓혀 파장보정 어긋남을 확인" 시나리오는 성립하지
> 않는다 — shift는 애초에 경계에 안 닿는다.

수정 후 보폭을 충분히 주면 \|ac1\| 0.03, NO2 1.4 ppb, `perr_rel`이 0.186→0.068로
2.7배 개선된다. **추천 창이 675-1470 poly6 → 675-1270 poly8로 바뀐다.**

### 단, 운영 FitSet은 이 추천이 아니다

운영 PNs는 px 899–1450 · poly3(444.1~470.6 nm)로, 수정 전 추천(675-1470 p6)과도
수정 후 추천(675-1270 p8)과도 다르다. **운영 세팅은 이 Stage-1 결과에서 나온 게
아닐 가능성이 높다.** 그래도 이 스코어카드를 근거로 내린 판단이 과거에 있었다면
전부 무효다.

### 수정 후 step 0.5에서 0/64가 되는 이유 — 남은 설계 결함

Stage-1의 `RP`는 `sh_val "-2,2"` + `step_limit 0.5`인데, 표본 스캔은 시간연속이
아니라 **매번 shift 0에서 출발**한다. 실제 PNs shift는 −1.96이라 한 스텝(0.5)으로는
도달할 수 없다 → 전량 경계.

`core/param_optimizer.py`는 이 문제를 `_seed_shift`(전역 격자탐색)로 이미 풀어놨고
주석에 이유까지 적혀 있다("★초기 shift 시딩(필수)… x0=0에서 least_squares만 돌리면
멀리 있는 진짜 최소를 못 찾고 0에 주저앉는다"). **`fit_optimizer.fit_window`에는
그 시딩이 없다.** 알파 정규화와 같은 계열의 누락이다.

→ **고치지 않았다.** Stage-1의 탐색 의미를 바꾸는 설계 변경이고 사양서 범위 밖이라
   판단을 넘긴다. 고친다면 `param_optimizer._seed_shift`를 재사용하는 게 맞다
   (두 함수는 문서상 같은 계열 — "fit_optimizer.fit_window의 확장").

## A-5. ch ↔ roi 매핑 모순이 한 군데 더 있다

`tools/optimize_fitrange.py`의 `pick_refdir()`는 알파 nm축과 Calib nm 범위의
**겹침**으로 wavecal 폴더를 고른다. PNs 알파(400.0~498.9 nm)에 대해 **`roi2`**를
골랐다 — `channel_map.json`의 ch2=PNs=**roi1**과 반대다.
roi1·roi2가 둘 다 같은 nm 대역을 덮으면 겹침 기준은 원리적으로 구별을 못 한다.

이로써 알려진 모순은 다섯 곳이다(README / `data_io.py:261` 주석 / `channel_map.json`
/ FitSet `channels.2` / `pick_refdir`). **하드웨어 확인 전까지 미해결로 둔다.**
본문 §11-5와 같은 항목이다.
