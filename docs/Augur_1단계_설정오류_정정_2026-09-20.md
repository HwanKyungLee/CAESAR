## A. roi 뒤바뀜은 **버그가 아니다** — "고치고 알파 재생성"을 하면 안 된다

### 재현한 사실 (동일)

`alpha_purge60/26yeosu/2026-05-18/alpha/ch1/2026-05-18-001_ANs_alpha_trace.dat`
헤더의 `wavelength_nm`(2048점)을 두 축과 직접 대조:

| 대조 | 중앙 \|Δ\| |
|---|---|
| roi1 `Calib_20260619_Hg_400-499nm_Poly2.txt` | 0.029648 nm = **+0.614 px** |
| roi2 같은 파일 | **0.000025 nm = 일치** |

T3의 측정은 정확하다. (`C:\Doasis_Work\...`와 `C:\GHL\2026 yeosu\...` 두 사본 모두 동일.)

### 그런데 운영 fitset이 ch1 → **roi2** 다

`fit setting` 폴더의 7개 fitset을 전부 열어 채널→ROI 매핑을 뽑았다:

| fitset | ch1 | ch2 | ch3 |
|---|---|---|---|
| **ANs[430-462]_PNs[444-471]_cold[438-476] (2026-09-17)** | **ANs→roi2** [429.5–461.9] | **PNs→roi1** [444.1–470.6] | cold [438.4–475.8] |
| ANs[430-466]_..._cold[438-466] | PNs→roi1 [429.7–466.0] | ANs→roi2 | cold [438.0–465.8] |
| 〃 `.bak_20260722_labelswap` | ANs→roi1 | PNs→roi2 | 〃 |
| ANs[430-466]_..._cold[438-450] (+bak) | 동일 패턴 | | |
| CH1[430-462]_CH2[444-471]_cold[438-476] (+bak) | 동일 패턴 | | |

두 가지가 보인다.

1. **2026-07-22 "labelswap"은 `data_label`만 바꿨다** (ANs↔PNs). `wl_path`는 그대로
   ch1→roi1, ch2→roi2였다.
2. **2026-09-17 fitset만 `wl_path`까지 바꿔 ch1→roi2, ch2→roi1이 됐다.**
   그리고 이 fitset의 창이 아카이브 산출물 폴더명과 정확히 일치한다 —
   `ch1_429.5~461.9__ch2_444.1~470.6__ch3_438.4~475.8`, 파일명 `ANs_430-462nm_Poly4`,
   `PNs_444-471nm_Poly3`, `cold_438-476nm_Poly4`. **이것이 운영 설정이다.**

### 따라서

production 알파(ch1 = ANs)가 roi2 축을 쓰고, 운영 fitset도 ch1 = ANs → roi2다.
**알파와 핏이 서로 맞는다.** T3가 "반대 ROI"라고 판정한 것은 `--alpha-ref`를 roi1로
주었기 때문이고, roi1은 **구 fitset들의 매핑**이지 운영 매핑이 아니다.

> **권고 철회.** "roi1↔roi2를 고치고 알파 재생성"은 하면 안 된다. 현재 자기일관적인
> 사슬에 0.614 px 오차를 **집어넣는** 조치가 된다. 내가 앞 턴에서 이것을 1순위로
> 승인한 것도 철회한다.

**남는 것은 H2 그대로다**: 물리적으로 어느 ROI가 ANs 채널인가. fitset 이력이
`data_label`(2026-07-22)과 `wl_path`(2026-09-17)를 **따로따로** 바꿨다는 것은, 이
매핑이 실험적으로 확정된 적이 없다는 뜻이다. 이건 코드로 못 푼다 — **하드웨어 확인**
이다. 오차예산에는 버그가 아니라 **미확정 설정**으로 적어야 한다.

## B. T1은 운영이 아닌 설정으로 돌았다

T1 재현 명령의 `--fitset`은
`FitSet_ANs[430-466nm_P4]_PNs[444-471nm_P3]_cold[438-466nm_P4]_Std.json.bak_20260722_labelswap`
이다. 운영 fitset과 세 군데가 다르다:

| | T1이 쓴 `.bak` | 운영 (2026-09-17) |
|---|---|---|
| ch1 매핑 | ANs → **roi1** | ANs → **roi2** |
| ANs 창 | 429.7 – 466.0 nm | **429.5 – 461.9 nm** (4 nm 좁음) |
| cold 창 | 438.0 – 465.8 nm | **438.4 – 475.8 nm** (10 nm 넓음) |

창 폭이 다르면 픽셀 수·조건수·다항식 자유도가 달라지므로 **I₀ 민감도가 그대로일
이유가 없다.** 특히 cold는 창이 10 nm 차이다.

그리고 **ANs/PNs 비대칭(8.10 % vs 3.55 %)의 해석도 달라진다.** Claude Code는
"T1은 production α를 안 쓰므로 roi 버그의 그림자가 아니다"라고 반박했고 그 논리는
맞다 — 하지만 T1이 쓴 fitset은 ch1을 **roi1**에 묶은 판본이라, T1의 "hot ANs"는
**운영의 hot ANs와 다른 물리 채널일 수 있다.** 즉 비대칭이 채널 라벨과 함께 뒤집힐
여지가 있다.

> **T1 재실행 시 `--fitset`을 운영본으로 바꿀 것.** 이게 조건 ⑤다.
> (①f 고정 ②step_limit ③7일 ④게이트 에 추가)

## C. 알파 헤더가 말하는 것 — `PCHIP(idx)`가 아니다

확인한 알파 파일 헤더:

```
# channel=1  label=ANs
# RL_factor=1.0  d=51.8 cm
# I0_mode=PCHIP(t)  ZA_count=1313
# Calibration: external R(t) — R_CH1.npz (1261 knots, 2 segments)
```

**`PCHIP(t)`이고 ZA_count=1313이다.** Claude Code가 보고한 `PCHIP(idx)` / `ZA_count=749`와
다르다 → **알파 세트가 여러 벌 있다.** 어느 것이 아카이브 결과를 만든 산출물인지
확정해야 한다. `PCHIP(idx)` 판본이 아카이브에 쓰였다면 C-2(실시각 전환)는 유효한
지적이고, `PCHIP(t)` 판본이라면 이미 해결된 항이다.

또한 `R_CH1.npz`가 **1261 knots, 2 segments**다 — 이전 R(t) 민감도 분석이 쓴
"3-knot 파일"과 전혀 다르다. **R(t) 항(3.30 %)의 근거 파일도 운영본인지 재확인해야
한다.** 1261 knot이면 knot 간격이 분 단위이고, 보간 오차는 3-knot 가정보다 훨씬 작다.

## E. 그대로 유효한 것

* T1의 **방법**(LOO, 스케일/모양 분리, α 수용 게이트, 증폭 실측)은 건전하다.
  틀린 것은 설정이지 설계가 아니다.
* T1의 헤드라인 과대추정 판정과 그 원인 4가지(n, 동반종 병적 거동, ef 전환, 경계 고착)는
  유효하다. Claude Code가 오염을 재집계해 `full` 행 기준 ANs 9/11·PNs 6/11로
  더 심하다고 정정한 것도 받아들인다.
* **게이트 규칙은 Claude Code 판이 맞다.** "같은 상쇄 구조를 갖는 관측량으로 검정한다" —
  채널 독립 항은 ΣANs로, 공통 항은 채널 시계열로. 내 원안(총 변동)은 채널 NO₂에 걸면
  25.9 %라 아무것도 못 잡는다. 수치 게이트 채널당 ≤ 0.059 ppb도 타당하다.
* T3의 나머지(캠페인 중 Hg 검정 없음 = UNQUANTIFIED, 실패 피팅 2건 배제,
  cold −11 px, roi1 축의 판본 간 1.5 px 기울기)는 전부 유효하다.
