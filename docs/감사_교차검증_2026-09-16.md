### 3-4. 공분산이 핏과 다른 계를 쓰던 것 — `9d0a87b`  [증명]

**원래 지적은 하나였는데 세 개가 나왔다.** 전부 λ>0 일 때만 드러난다.

| | 어긋난 것 |
|---|---|
| ① | `lam = tikhonov_lambda` 로 되돌려 `override_lam` 을 버렸다 → 정규화 A로 핏하고 오차는 B로 계산 |
| ② | 증강이 `[A; diag(λ)]c≈[y;0]` 이라 정규방정식은 `(AᵀA + λ²I)c = Aᵀy`. **실효 릿지는 λ²** 인데 공분산은 `AtWA + λ·I` 를 썼다 |
| ③ | `_penalty()` 는 Chebyshev 배경열을 **일부러 0** 으로 두는데(표준 DOAS) 공분산은 `λ·eye` 로 전 열 균일 수축 |

**②의 수치 증명**

```
코드 증강해 vs (AᵀA+λ²I)⁻¹Aᵀy  차이 = 5.6e-16   <- 일치
코드 증강해 vs (AᵀA+λ I)⁻¹Aᵀy  차이 = 8.2e-03
```

**고친 방법**: 핏이 쓴 페널티 행렬 `P` 를 그대로 받아 **`M = AᵀA + PᵀP`**.
증강계 `[A; P]` 의 정규방정식과 **정의상 동일**해서 셋이 한 번에 닫힌다.

**직접 확인하는 법**


λ 가 정말 전부 0인지 직접 확인:

### 3-5. σ̂² 분모 `RSS/n` → `RSS/(n−p)` — `82a293f`  [증명] + **출력 변화**

**문제였던 것**: `mse = np.mean(resid_w**2)` = RSS/n 은 최대우도 추정자지만 **편향**돼 있다.
불편추정자는 `RSS/(n−p)`. 그래서 `<gas>_Error` 와 `MDL = 3×Error` 가
`√(n/(n−p))` 배만큼 **작게** 보고되고 있었다.

**왜 이게 위험한 방향인가**: 오차를 작게 보고하는 것은 **실제보다 정밀하다고 주장하는 것**이다.
MDL 도 같이 내려가서 "검출했다"고 말할 수 없는 걸 말하게 된다. 반대 방향이면 보수적이라
넘어가도 되지만 이건 아니다.

**크기**: 여수 ANs 창(n≈667 · p≈10) 기준 **약 0.8 %**. NO2 `perr/conc` 1.70 % → 1.72 %.

**맥락 — 이게 중요하다**: 오차예산에서 이 항의 비중은 작다.

```
NO2 핏 공분산 항         1.70 %  ->  1.72 %   (차이 0.013 퍼센트포인트)
단면 문헌 불확도(계통)   3~5 %                 <- 가장 큰 항, 아직 UNQUANTIFIED
σ(R) → 경로길이          UNQUANTIFIED
캐비티 d·R_L             UNQUANTIFIED
잔차 고정패턴(콜드)      UNQUANTIFIED
```

**즉 "고쳐야 정확해진다"가 아니라 "오차예산 표의 맨 윗줄이 교과서대로여야 한다"의 문제다.**

**직접 확인하는 법**

```bash
python tools/test_covariance_lambda.py
```

이 테스트는 가짜 엔진으로 **실제 `execute_varpro_fit` 을 태우고**, 설계행렬
`A = [gas | Chebyshev | sin | cos]` 를 재구성해 닫힌형과 대조한다:

```
perr  ==  sqrt( diag((AᵀA)⁻¹) · RSS/(n−p) )      rtol 1e-6
```

분모가 `n` 으로 되돌아가면 실패한다. "이 표본에서 `n`과 `n−p`가 실제로 구별되는가"도
같이 단언해서 테스트가 무의미해지는 경우를 막았다.

**출력 변화**: **있다.** 모든 `<gas>_Error`·`<gas>_MDL` 이 약 0.8 % 커진다.
**기존 export 와 새 export 가 그만큼 다르다** — 결과 헤더의 git 해시로 구분된다.

**⚠ 같이 알아둘 것**: `p = len(theta0) + A_f_w.shape[1]` 로 센다. worker 의 Chi2용
`n_params` 공식은 `custom_basis`(Ring·고정패턴)를 못 세므로, 그걸 켜는 날 두 DOF 가 갈린다.

**"실제 핏 잔차는 강하게 상관(|ac1|~1)"** 이라고 **근거 없이 단언**하고 있었는데

읽히므로, 이걸 전제로 뭘 재설계하면 잘못된 방향으로 간다. 실측 숫자로 교체했다.
(보정 자체는 유효 — 핫 ρ≈0.44 → n_eff ≈ 0.39n.)

**직접 확인하는 법**

```bash
python tools/test_n_eff_floor.py
```

ρ 분포를 직접 다시 재려면 `core.window_designer.residual_rho` 를 창·poly 격자로 돌린다
(채널 키는 `cold` / `ans` / `pns`).

**출력 변화**: 없음.

## 6. 당신 확인이 필요한 것

### 6-1. 랩뷰 — row 0 의 적분시간·판독 방식이 실측행과 같은가

**왜 필요한가**: 헤더행 RMS 가 같은 파일 중앙값의 2.8~7.6배인데 **원인을 모른다.**
T/P 는 원인이 아님이 §4에서 증명됐다. 남은 후보:

* I0/shift 미정착? → 그런데 같은 파일 row 1 도 조건이 같은데 row 1 은 정상이다
* 노출 조건이 다른가? → `corr=1.0000` 이지만 **corr 은 배율에 둔감해서 적분시간 차이를 못 잡는다**

랩뷰에서 이것만 확인하면 후보가 정리된다. **랩뷰 코드를 고칠 필요는 없다**(§7-3).

### 6-2. 오차예산 — 내가 만들 수 없는 숫자

| 항 | 필요한 것 |
|---|---|
| 단면 문헌 불확도 | Vandaele 2002 / Volkamer 2005 / Thalman 2013 의 인용 불확도. **가장 큰 항일 가능성** |
| 캐비티 d·R_L | d=51.8 cm, R_L 0.9330/0.9950/0.9968 은 실측인데 **불확도가 미기록** |

내가 계산 가능한 것: σ(R)→경로길이 (`R_*.npz` 의 `knot_sec`·`omr_d`·`wave_nm` 산포),
잔차 고정패턴 몫.

### 6-3. 콜드 ILS 요동 — 버려진 62.6시간분이 살아날 수 있다

```
FWHM_Analysis_20260602 :  3.41 ~ 3.55 nm
FWHM_Analysis_20260610 :  0.77 ~ 0.86 nm
필드로그 5/23          :  3.7 nm → ~1 nm
```

콜드 FWHM 이 **최소 두 번 4배 오갔는데** 핏은 단일 FWHM 레퍼런스를 캠페인 전체에 쓴다.
QC 가 버린 구간이 "측정 불량"이 아니라 **"레퍼런스 컨볼루션 불일치"**일 수 있다.

## 7. 안 고치기로 한 것과 그 이유

### 7-1. 자동 QC `K` 값

| K=8 실제 동작 | 콜드 | 핫/ANs |

버려지는 게 뭔지도 안다 — `corr(log SNR, log RMS) = −0.797`, **저광 조건의 실측 스캔들**.
원칙 1(과필터링이 부족한 필터링보다 위험) 정면 위반.

그리고 콜드 8.83 % 는 골고루가 아니다: **일자별 median 0.0 %**, 33일 중 28일은 한 행도
안 잘린다. 4일(05-23 · 05-27 · 06-02 · 06-17)에 몰려 있고 **전부 계단형**이며 필드로그가
