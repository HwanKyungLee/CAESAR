### 제로에어 창은 13초에 정착한다 (60초가 아니다)

0 sccm 베이스라인으로 60초로 늘린 `502` 블록(`2026-08-10-005`, 64행)을 행별로 보면:

```

t=13~61s  정착:  PNs 14780 ± 40,             ANs 13520 ± 30
```

**늘린 판단은 옳았다** — 뒤쪽 48초(약 50스캔)가 깨끗한 제로에어다. `purge_settle_sec`(기본 60초)와
혼동하지 말 것: 그건 **교정 → 대기** 회복 시간이고, 대기 → 제로에어는 훨씬 빠르다.

정상 주기의 `500`/`510` 블록은 앞에 `502`/`512` 가 27초 먼저 돌아서 **첫 행부터 평평**하다
(`2026-08-10-004` 실측 전반/후반비 PNs 1.0009 · ANs 0.9995). 이 절의 문제는 **인젝션 파일 한정**이다.

### 그런데 앞 과도구간이 I0 에 섞여 들어갔다

`gui/worker.py` 의 `_block_average` 가 블록을 통째로 `np.nanmean` 했다 — I0 쪽엔 정착 구간
잘라내기가 없었다(`purge_settle_sec` 는 Pass 2 의 ambient 에만 걸린다).

| | PNs | ANs |
|---|---|---|
| I0 편향 (64행 전체 / 정착 50행) | +1.54 % | +2.85 % |
| poly3 제거 후 잔차(중앙 1024 px) | 0.52× | 1.31× 실측노이즈 |
| **투영한 NO2 편향** | **-0.078 ppb** | **-0.094 ppb** |

투영 = Δα 를 운영 레퍼런스 + poly3 + 에탈론 f=0.12 에 선형 최소제곱(shift -1.96 px 고정).
Δα 의 RMS 를 손으로 농도 환산하면 안 된다 — **다항식이 대부분 흡수한다**.

**g(=0.82)는 영향받지 않는다.** 두 채널이 같은 방향으로 밀려서 **비에는 0.2 % 만** 남는다.
이건 아래 "실험 A" 절이 이미 말한 논리(미정착은 두 채널에 똑같이 곱해져 비율에서 상쇄된다)의
정량 확인이다. 다만 **절대 ppb 에는 채널당 약 1 % 가 들어간다** — "핫 30 % 저읽음"에 비하면
작지만, 절대보정 작업을 할 땐 빼고 시작해야 한다.

이 항은 **평균해도 안 줄어든다**: 파일의 전 스캔이 같은 I0 를 쓰는 고정항이다.

### 수정 (2026-09-21 적용)

`gui/worker.py` 에 모듈 레벨 `settle_start(block, tol=SETTLE_TOL)` 를 두고 `_block_average` 가
블록마다 선두 과도구간을 잘라낸다.

* 기준은 블록 **뒤쪽 1/3 의 중앙값**, 문턱 `SETTLE_TOL = 0.02`
  (정착 산포 ~0.3 % 와 과도구간 14~21 % 사이).
* **마지막으로** 벗어난 행 다음까지 버린다. "처음 들어오는 행"에서 멈추면 안 된다 — 과도구간은
  단조롭지 않다(실측 PNs 가 14492 로 한 번 들어왔다 15481 로 다시 나간다). 조기중단하면 7행만
  버리고 과도구간 절반을 남긴다.
* 8행 미만 블록, 전부 NaN 인 행이 있는 블록, **절반 넘게 버려야 하는 블록**은 트리밍하지 않는다
  (마지막 경우는 블록 전체가 의심스럽다는 뜻이고, 조용히 일부만 I0 로 쓰는 게 더 위험하다).

  **0 이면 블록이 이미 정착해 있었다는 뜻**이고, 값이 있으면 그 I0 는 wait-before 를 쓴 것이다.

## raw 파일 컬럼/flag 가공 로직 (8/10에 실제로 한 것 — 재사용 가능)

**왜 필요했나**: 인젝션 실험은 raw 파일의 flag=500(ZA-inject) 상태 동안 실제로는 NO2를 섞어서 넣었다.
그래서 이 flag가 "진짜 zero-air 기준"이 아니라 "NO2 샘플 데이터"였는데, 파이프라인은 flag=500을 항상
I0(제로에어 기준) 후보로 읽는다. **flag 값을 물리적 실제 상태에 맞게 다시 붙여야** 알파/R 계산이 맞다.

### raw 파일 구조 기본 (`core/raw_parser.py` 가 정본)
```
col 4       : state flag (0=헤더/파일시작, 1=ambient/sampling, 500=ZA-inject, 502=ZA-wait-before,
              510=He-inject, 512=He-wait-before, ...)
col 5:2053  : 빈 구간(2026 데이터는 노이즈)
col 2053:4101   : PRIMARY 스펙트럼 (Hot: PNs 셀)
col 4101:6149   : SECONDARY 스펙트럼 (Hot: ANs 셀)
col 6149+   : HK(하우스키핑) 블록
```
파싱은 `core.data_io.extract_raw_file_for_parallel((path, pixel_min, pixel_max, channel))` 한 번으로
`flags, T, P, specs, secs` 배열을 얻는다 — 이게 GUI Pass1과 완전히 같은 함수라 이걸로 미리 검증 가능.

### 진단 체크리스트 (Alpha Gen 돌리기 전에 먼저 확인)
```python
from core.data_io import extract_raw_file_for_parallel
_, flags, Ts, Ps, specs, secs = extract_raw_file_for_parallel((path, 0, 2048, ch))  # ch=1,2
za_idx = np.where(flags==500)[0]; he_idx = np.where(flags==510)[0]
```
1. **flag=500(ZA) 행이 충분히 있는지** — 없으면(예: wait-before 502만 있음) I0/R 계산 불가
2. **포화 확인**: `specs[idx].max()`가 65534~65535에 가까우면 그 상태는 못 씀(16비트 ADC 한계)
3. **He/ZA contrast**: `(He평균-ZA평균)/He평균`이 fit window 안에서 +5%는 넘어야 함(He가 ZA보다 밝아야
   정상 — 헬륨은 산란/흡수가 거의 없어서 빛이 더 많이 통과)

### flag 재라벨링 레시피 (텍스트 파일이라 tab 토큰 하나만 바꾸면 됨)
파일은 한 줄=한 스캔, tab 구분. flag는 col index 4(0-based). 다른 컬럼은 절대 건드리지 말 것.
```python
toks = line.split("\t")
if <조건>: toks[4] = "<새플래그>"
fout.write("\t".join(toks) + "\n")
```
8/10에 실제로 쓴 조합(순서대로 겹쳐 적용):
1. **NO2 주입 구간(500)→1(ambient)**: 실제 도징이 일어난 flag=500 블록을 ambient(1)로 재라벨 —
   이래야 Alpha Gen이 이걸 "샘플"로 취급해서 concentration fit 대상으로 잡음
2. **wait-before(502)→500(ZA-inject) 승격**: 파일 자체에 진짜 zero-air 안정구간이 없을 때, 도징
   직전의 502(아직 정착 전, ~5% 노이즈 큼, 문서화된 값)를 500으로 승격해서 I0/R 계산에 씀. 물리적으로
   004(1.5시간 전) 같은 **다른 시각의 파일보다 시간적으로 훨씬 가까운 502가 더 나음**(LED 드리프트로
   1.5시간 차이에도 세기가 44% 차이나는 게 실측 확인됨 — 시간 근접성이 정착 여부보다 중요할 수 있음)
3. **He만 다른 파일에서 갖다 쓰기**: raw CH2 He가 이번 세션만 포화됐을 때, 같은 row 범위(flag=510)를
   시간이 가까운 다른 파일(004)에서 그대로 복사해 붙임 — He는 반사율(R) 계산용이라 ZA보다 시간 드리프트
   에 덜 민감(거울 반사율은 잘 안 변함), 그래서 이 대체가 ZA를 갖다 쓰는 것보다 안전함
4. **flag=0(헤더행) 스킵**: 이건 파일 재라벨링이 아니라 `gui/worker.py` 코드 버그였음(위 "찾아서 고친
   버그" #1) — raw 파일은 안 건드려도 됨, 코드가 이미 고쳐짐

   ```
   CH1(ANs) 라인 → 핫 셀에 그대로 (레퍼런스, 안 건드림)
   cell2 라인(오늘 NO2 도징에 쓴 그 라인, 총유량 ~500sccm) → 튜빙째 콜드 셀 인렛에 직결
   ```
   - **직결이라 원칙적으로 재계산 불필요** — NO2 sccm/총유량 비율이 안 바뀌니 오늘과 같은 MFC
     세팅이면 콜드에서도 같은 ppb가 나와야 함(cyl 농도가 어차피 미상이라 "이론값"이 아니라
     "핫에서 나온 값과 같은 값"이 곧 목표)
   - [ ] **단, 콜드 셀 자체의 최소 필요 유량부터 확인할 것** — cell2 총유량(~500, 오늘 실측
     readback으로 재확인)이 콜드 캐비티가 정상 압력/퍼지를 유지하는 데 충분한지 체크. 6/2 콜드
     자체테스트 관행(2000sccm)보다 한참 낮음 — 압력이 비정상이면 콜드 캐비티가 이 유량에서
     제대로 안 도는 것일 수 있으니, 연결 직후 R/Allan deviation 사전점검에서 압력값부터 볼 것
   - [ ] 만약 콜드가 500sccm으론 압력 부족하면: 부족분을 콜드 자체 순수 N2/ZA로 보충하되, 그 순간
     ppb 비교는 "핫과 동일"이 깨지므로 **보충한 유량만큼 희석비 다시 계산해서 콜드 쪽만 별도
     환산**(핫과 직접 비교가 아니라 정규화 비교로 전환)

2. 스텝 설계 — **정착 우선, 다이나믹레인지 욕심내지 말 것**

## 왜 하는가 — 풀려는 문제 두 개

1. **ANs 채널이득(g) 축퇴**: `ANs = ch1 − g·ch2` 회귀는 "이득이 g다"와 "ANs가 (g−1)×ch2만큼 진짜
   있다"를 구분 못 한다(같은 방정식). 실측 검증: NO₂ 비례 인공 ANs를 넣고 회수 테스트 → **회수율 0%**
   (창 길이 무관). 대기 자료만으로는 원리적으로 못 푼다 — 답을 아는 기준가스가 유일한 해법.
2. **핫 채널 30% 저읽음**: NIER 순천 상시측정 대비 cold 0.90~0.96, **hot 0.68~0.71**. R·공동길이·RL
   전부 무혐의 확인 끝남. ZA/He가 가열인렛보다 상류라는 것도 확인됨(→ 퍼지/R 가설 기각, 상쇄 논리 성립).
   남은 후보 = 가열인렛 손실 또는 핫 스펙트로미터 자체 캘리브레이션.

인젝션 하나로 둘 다 풀린다 — 답을 아는 가스를 넣고 실제로 몇 ppb로 읽는지 직접 재면 g와 절대 보정계수가
동시에 나온다.

관련 메모(세션 축적 메모리, 이 문서보다 최신일 수 있음 — 먼저 확인):
`no2-injection-design-2026-08`, `hot-channel-scale-deficit-30pct-2026-08`,
`ans-pre65-reconciliation-2026-07`, `hot-channel-identity-ch2-is-ans-2026-07`.

## 계산 방법 — 정식 물리식 (선형근사 쓰지 말 것)

**절대 이렇게 하지 말 것**: `강도감소율 ≈ alpha_NO2/omr_d` 같은 선형근사. 실제 농도대에서
`alpha_NO2`가 `omr_d`보다 커질 수 있어(15sccm 케이스에서 실제로 그랬음) 근사가 깨진다.

**정식 식**:
```
I/I0 = (omr_d + alpha_ZA_rayleigh) / (omr_d + alpha_ZA_rayleigh + alpha_NO2)
alpha_NO2 = sigma_NO2(피크파장) × N,   N = ppb × 1e-9 × n_air
n_air = core.fit_physics.air_number_density(T, P)
alpha_ZA_rayleigh = core.physics.RayleighPhysics.get_alpha_rayleigh(wave, T, P, 'zero_air')
```
역으로 실측 I/I0에서 ppb를 구하려면:
```
a_obs = (omr_d+alpha_ZA) × (I0/I − 1)
N_obs = a_obs / sigma_NO2(피크파장)
ppb_obs = N_obs / (1e-9 × n_air)
```

### 필요한 파일 (콜드)
- 파장축: `reference_data/wv_cal/cold/Calib_20260523_Hg_4line_400-497nm_Poly2.txt` (2048행, 픽셀당 1개)
- NO2 단면적: `reference_data/wv_cal/cold/Ref_NO2_Dynamic-ILS-Applied.dat` (헤더 3줄+2048행)
- R(t): `Output\R\R_cold.npz` (`knot_sec`=raw기록축, `omr_d`, `wave_nm`)
- 핏창: 438.4-475.8nm

### 필요한 파일 (핫, ch1/ch2 따로)
- ch1: `reference_data/wv_cal/roi1/`, 핏창 429.5-461.9nm, `Output\R\R_CH1.npz`
- ch2: `reference_data/wv_cal/roi2/`, 핏창 444.1-470.6nm, `Output\R\R_CH2.npz`
- raw 파싱: `core.data_io.extract_raw_file_for_parallel((path, 0, 2048, channel))` — channel=1 or 2

### 절차 (스크립트 골격)
1. raw 파일 파싱 → flags, T, P, specs, secs
2. 순수 ZA 구간(baseline)과 NO2 주입 구간(피크/정상상태) 각각 평균 스펙트럼 뽑기
3. 핏창 안에서 NO2 단면적이 최댓값인 픽셀(peak_i) 찾기
4. baseline=I0, 주입구간=I로 위 정식을 픽셀 peak_i에서 계산
5. (신뢰도 위해) 여러 유량단계 반복, ppb_obs와 유량의 선형관계 확인

⚠️ 이건 **단일 픽셀 광학두께 근사**다. poly baseline·다른 흡수체(H2O, CHOCHO) 간섭을 빼지 않은
단순화 버전 — 1차 확인용으로는 충분하나, **최종 결론엔 정식 다종 DOAS 핏을 권장.**
