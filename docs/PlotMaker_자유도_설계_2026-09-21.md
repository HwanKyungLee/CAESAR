# Plot Maker 자유도 설계 — "그림을 자유롭게 만드는 도구"로 (2026-09-21)

> **본편은 자유도다.** 데이터 진실성(flag·tz·결측·provenance) 항목은 §7 부록으로
> 내렸다 — 값은 있지만 이 논의의 주제가 아니었다.
>
> 이 문서는 **결정 기록**이다. 무엇을 하기로 했는지뿐 아니라 **무엇을 안 하기로
> 했고 왜인지**를 같이 남긴다.

## 1. 진단 — 왜 "자유롭게 못 만드는" 느낌이 드나

Plot Maker는 꾸미기(눈금 방향·길이·앵커, 라벨 pt/색/드래그, 테마·팔레트,
config/style 템플릿, Batch Publish)는 Origin 수준까지 갖췄다. 그런데도 답답한
이유는 하나다:

> **모드가 그림 전체를 소유한다.** 각 모드의 `render_mpl(fig)`가 안에서
> `fig.add_subplot(111)`을 직접 부른다(`modes.py:520`, Scatter는 `:723`).
> **그림 1개 = 모드 1개 = 축 1개.**

즉 Plot Maker는 *figure composer*(그림 작성기)가 아니라 *프리셋 갤러리*(6개 모드)다.
나머지 제약이 전부 여기서 파생된다.

| 하고 싶은 것 | 지금 | 막는 지점 |
|---|---|---|
| 한 그림에 시계열 + 산점도 나란히 | **불가** — 따로 뽑아 PPT/Illustrator에서 붙임 | 모드가 figure 소유 |
| inset (그림 안 작은 그림) | **불가** | 〃 |
| (a)(b)(c) 패널 라벨 · 패널 높이 비율 · 2열 배치 | **불가** — Split panels는 *같은 모드의 시리즈별* 1열 세로 스택 고정 | `modes.py:482 _render_mpl_split` |
| 텍스트 박스 · 화살표 · 구간 음영 · 박스 | ~~불가~~ → **M3에서 해결** | 주석이 무한 수직/수평선 2종뿐이었다 |
| bar / step / area / band / 오차막대 캡 | ~~불가~~ → **M4에서 해결** | 시리즈 스타일이 width·dash·marker·msize 넷뿐이었다 |
| y축 3개 이상 | **불가** | L/R 고정 (§5에서 기각 — 수요를 못 봤다) |
| 화면에서 선 클릭 → 색·두께 변경 | **불가** | 드래그 되는 건 라벨 4개뿐 (§5 보류) |
| NO₂ 아래첨자 · ×10⁻⁹ · μg m⁻³ | ~~깨진다~~ → **M5에서 해결** | 화면은 pg HTML(`<sub>`), Publish는 mpl mathtext(`$_2$`) — 서로 다른 문법이라 뭘 쳐도 한쪽이 literal이었다 |

마지막 줄은 자유도 이전에 **버그에 가깝다.** 논문 그림에 가장 자주 필요한 게
아래첨자인데 지금은 화면과 출력 중 하나를 포기해야 한다.

## 2. 레퍼런스 — 무엇을 훔치고 무엇을 안 훔치나

| 도구 | 훔칠 것 | 안 훔칠 것 |
|---|---|---|
| **OriginPro** | 레이어(패널) 자유 배치, inset, 미니 툴바(객체 클릭 → 즉시 편집), 템플릿 | 무제한 레이어·수백 개 그래프 타입. 우리 6모드로 충분 |
| **GraphPad Prism** | 파일 하나 = 데이터+분석+그림 (우리 `.pmcfg.json`이 이미 그 역할) | 통계 마법사 |
| **Igor Pro** | 그림 위 객체를 좌표계(데이터/축비율) 골라 배치 | 자체 스크립트 언어 |
| **matplotlib gridspec / ggplot facet** | 그리드 + 비율 + 공유축 문법 | grammar-of-graphics 엔진 전체 |
| **Illustrator / Inkscape** | — | **전부.** 마지막 5%(베지어, z-order 패널, 그룹/언그룹)는 SVG 내보내서 거기서 한다. 여기서 이기려 들면 Augur가 그래픽 툴이 된다 |

## 3. 설계 — 자유도를 올리는 6수

> **진행 상태 (2026-09-21)**: M4·M5·M3 **구현 완료**(검증 `python tools/validate_plotmaker.py`
> 25·26·27번 항목). M-P·M1·M2는 §4 결정 후.

### M4. 시리즈 표현 타입 *(1순위 — 완료)*

**문제**: 시리즈는 "선 + 마커"밖에 못 된다. 막대·계단·면·밴드·오차막대가 없다.

**설계**

- `ResolvedSeries`에 필드 **하나** 추가: `kind: str = "line"`.
  값: `line` / `marker` / `step` / `bar` / `area`(0까지 채움) / `band`(짝 시리즈 사이 채움) / `errorbar`(캡 있는 막대).
- 두 렌더러가 그 필드로 분기한다. pg: `stepMode`, `BarGraphItem`, `FillBetweenItem`,
  `ErrorBarItem`. mpl: `drawstyle="steps-post"`, `bar`, `fill_between`, `errorbar`.
- 시리즈 스타일 다이얼로그(`modes.py:353`)에 `Type` 콤보 + `Alpha`(투명도) 추가.
- `band`는 시리즈 2개를 묶어야 하므로 **시리즈 목록에서 2개 선택 → "밴드로 묶기"**.
  묶인 쌍은 목록에서 한 항목으로 접힌다.

**불변식**: `kind`는 `_resolve_specs()`에서만 결정된다. 두 렌더러는 분기만 하고
새로 계산하지 않는다(ResolvedSeries 규약 유지 — 이게 깨지면 화면·출력 드리프트가
돌아온다).

**검증**: `validate_plotmaker.py` 25번.

**구현 메모 (실제로 한 것)**

- `kind`는 `_styles[label]` dict에 들어가 `.pmcfg.json`에 **자동으로 따라붙는다**
  (`to_config`가 `styles`를 통째로 저장하고 있었음 — 새 필드 추가 코드 불필요).
  `_style_of()`가 빠진 키를 기본값으로 채우므로 옛 설정도 그대로 열린다.
- **계단은 라이브러리 옵션을 안 쓴다.** pg(`stepMode='center'/'left'/'right'`)와
  mpl(`drawstyle='steps-pre/post/mid'`)의 의미가 미묘하게 달라, `processing.step_xy()`가
  좌표를 직접 펴고 **양쪽 다 '그냥 선'으로 그린다** → 두 렌더러가 같을 수밖에 없다.
  계단일 때 마커는 편 좌표가 아니라 **원래 점 위치**에 따로 찍는다(안 그러면 점이 2배).
- `band`의 짝은 **목록의 바로 다음 시리즈**(드래그로 순서 변경 가능하니 충분).
  짝이 없으면 죽지 않고 선으로 폴백한다.
- `errorbar`는 기존 `± Error band (1σ)` 체크의 값을 그대로 쓴다 — 밴드 대신 캡 막대로
  그리고, 밴드와 중복해서 그리지 않는다.

### M5. 라벨 마크업 통일 *(2순위, 사실상 버그 수정 — 완료)*

**문제**: 위 표 마지막 줄. 같은 문자열이 화면과 출력에서 다르게 렌더된다.

**설계**

- **입력 문법은 mathtext 하나로 정한다** (`NO$_2$`, `$\times 10^{-9}$`, `$\mu$g m$^{-3}$`).
  이유: 최종 산출물이 mpl이고, mathtext는 논문 관례고, pg HTML은 우리만의 방언이다.
- `pg_label`/`_DraggableLabel`에 들어가기 직전 **mathtext → pg HTML 변환기** 하나를
  둔다. 전부는 필요 없다 — `_{...}`/`^{...}`/`\mu`/`\times`/`\alpha`/`\sigma` 정도의
  **화이트리스트 매핑**이면 실사용의 99%다. 모르는 토큰은 **원문 그대로 통과**시킨다
  (조용히 지우면 사용자가 뭘 잘못 쳤는지 모른다).
- 변환은 라벨·범례 이름·주석 텍스트가 **모두 같은 함수**를 거친다(원칙 ③).
- 좌측 패널 라벨 입력칸 툴팁에 예시 3개를 박는다.

**검증**: `validate_plotmaker.py` 26번 (7케이스).

**구현 메모 — 중간에 잡은 함정 하나**

처음엔 문자열 전체에 `_`/`^` 치환을 걸었다가 **`R_mean`·`NO2_Error` 같은 컬럼명이
아래첨자로 둔갑**하는 걸 발견했다. 범례 이름이 컬럼명에서 오므로 실사용에서 바로
터졌을 버그다. → **`$…$` 안에서만 수식으로 해석**한다(mpl과 같은 규칙). 밖의
밑줄은 그냥 밑줄이다. 이 케이스는 검증에 박아뒀다.

### M3. 주석을 진짜 레이어로 *(3순위 — 완료)*

**문제**: 주석 = 무한 수직선·수평선 2종. 그림에 "여기서 필터 교체" 같은 말을 못 쓴다.

**설계**

- 주석 종류 확장: 기존 `vline`/`hline` + **`text`(박스·테두리·배경 선택),
  `arrow`(점 → 라벨), `vspan`/`hspan`(구간 음영), `rect`**.
- 각 주석은 **좌표계를 고른다**: `data`(데이터 좌표, 줌 따라감) / `axes`(축 비율
  0~1, 줌 무관). Igor/Origin이 이 구분을 두는 이유는 "그림 왼쪽 위에 (a)" 같은 건
  데이터와 무관하게 붙어 있어야 하기 때문.
- 배치는 **기존 인프라를 쓴다** — 신설이 아니라 확장:
  - 그래프를 클릭해 좌표를 찍는 흐름: `_annot_pick`(`widget.py:133`)이 이미 한다.
  - 드래그 이동: `_DraggableLabel`(`modes.py:27`)을 주석에도 붙인다.
- 렌더: pg = `TextItem`/`ArrowItem`/`LinearRegionItem`/`QGraphicsRectItem`,
  mpl = `annotate`/`axvspan`/`axhspan`/`Rectangle`.
- 야간 음영(`_night_spans`)은 **그대로 둔다** — 자동 계산이라 성격이 다르다.

**불변식**: 주석은 `_annots` 리스트 하나가 단일 출처고, pg·mpl 양쪽 그리기 경로가
그 리스트만 읽는다. (2026-07-06에 "mpl은 legend label로만 넘겨 범례 끄면 증발"한
버그가 있었다 — 가드 17번. 새 주석 종류도 같은 가드에 넣는다.)

**검증**: `validate_plotmaker.py` 27번 (가드 17번의 확장).

**구현 메모 — 설계에서 바뀐 것 둘**

1. **좌표계 선택(data/axes)은 안 넣었다.** `axes`(축 비율) 좌표는 pg에서 줌하면
   어긋나 화면≠출력이 되고, 그 주 용도인 "그림 왼쪽 위에 (a)"는 M2 Composer의
   패널 자동 라벨이 훨씬 싸게 해결한다. **전부 데이터 좌표**로 간다.
2. **구간 음영의 라벨은 '펜 없는 InfiniteLine'에 붙였다.** 주석은 `clear_plot()`
   시점, 즉 **데이터를 그리기 전**에 그려져서 뷰 범위를 모른다 → 라벨 위치를 직접
   계산할 수가 없다. pg의 InfiniteLine 라벨은 그 위치 계산을 스스로 하므로, 보이지
   않는 선 하나에 라벨만 얹어 재사용했다.

레코드 스키마도 바꿨다: `{"kind","val",…}` → `{"kind","x1","y1","x2","y2",…}`.
읽는 쪽 `_annot_norm()`이 옛 레코드를 올려주므로 기존 설정·세션은 그대로 산다.

**덤으로 고친 것**: 주석은 지금까지 **아무 데도 저장되지 않았다** — 설정을
불러오면 조용히 사라졌다. `.pmcfg.json`에 `annots`로 저장한다(데이터 좌표에 묶인
그 그림만의 것이라 style 템플릿이 아니라 plot config 쪽이 맞다).

### M-F. 출판 폰트 처리 *(추가 — 완료)*

레퍼런스 조사(Copernicus = ACP·AMT 저자 규정: "벡터 우선, **폰트 임베딩 필수**,
한 폰트 패밀리, sans-serif 권장")를 우리 코드와 대조하다 **기본값이 정반대**인 걸 찾았다.

| 항목 | 전(mpl 기본) | 후 | 왜 |
|---|---|---|---|
| `pdf.fonttype` / `ps.fonttype` | **3** (Type 3) | **42** (TrueType) | Type 3는 임베딩돼도 **투고 시스템이 거부하는 곳이 있다**(IEEE·AAAI 사례). 그림은 멀쩡한데 제출에서 막히는, 제일 늦게 발견되는 사고 |
| `svg.fonttype` | **`'path'`** | **`'none'`** | 기본값은 글자를 패스로 박아 **Illustrator/Inkscape에서 편집 불가**. 우리 설계가 "마지막 5%는 SVG로 넘긴다"인데 그 길이 막혀 있었다 |

실제 파일로 확인: PDF에 `/Subtype /Type3` **0개**, `/Subtype /CIDFontType2` +
`/FontFile2` **1개**(= TrueType 임베딩). SVG는 `<text>`가 살아 있다.

**대가와 분업**: `svg.fonttype='none'`은 여는 쪽에 그 폰트가 없으면 대체 글꼴로
보인다. → **배포·열람은 PDF**(폰트가 파일 안에 들어 있음), **편집은 SVG**로 나눠 쓴다.

⚠ EPS 출력을 나중에 붙일 때: mpl에 Type 42 + EPS 조합 버그가 보고돼 있다
(matplotlib#27328) — 그때 실제 파일로 확인할 것.

### M-C. 색 접근성 *(추가 — 완료)*

**Okabe-Ito 범주형 팔레트** — 세 가지 색각이상(P·D·T)에서 모두 구분되게 설계된
사실상의 표준(R 4.0+ 기본, Nature/Science 계열 권고). `_FAMILIES`(한 색의 진↔연)와
성격이 달라 `_CATEGORICAL`로 따로 두고, `_apply_palette`가 목록을 순서대로
돌려 쓴다(8개 초과면 순환). ⚠ 5번째 노랑 `#F0E442`는 흰 배경 가는 선에서 흐리다 —
툴팁에 적어뒀다.

**상관 히트맵 `bwr` → `RdBu_r`**

- `bwr`의 문제는 *적녹 대비가 아니다*(청-백-적이다). 실제 문제는 ① 양 끝이 완전
  채도라 |r| 차이가 뭉개지고 ② 한가운데 순백이 급격한 명도 단절을 만들어 **없는
  경계가 있는 것처럼** 보이며 ③ 흑백 인쇄 시 ±가 같은 회색이 돼 부호가 사라진다.
- **`_r`이 핵심**: `RdBu`는 빨강(낮음)→파랑(높음)이라 그냥 쓰면 상관 **부호가 조용히
  뒤집힌다**. 그림은 멀쩡해 보여서 아무도 못 알아챈다. 검증 30번이 pg·mpl 양쪽에서
  `-1=파랑, +1=빨강`을 확인한다.

**셀 글자색을 배경 휘도로** — 옛 규칙 `abs(r) > 0.5 → 흰색`은 컬러맵에 묶인 상수라
교체와 함께 어긋난다. 재보니 **바꾸기 전에도 이미 틀려 있었다**: `bwr`은 |r|=0.9에서도
검은 글자 대비가 더 좋다(5.40 vs 3.89). 이제 WCAG 상대휘도 < 0.179에서만 흰 글자를
쓴다 — 컬러맵을 또 바꿔도 따라온다. 실측 확인: `RdBu_r`에서 0.50·0.60 검정, 0.80 흰색.

### M-E. 출판 규격: EPS + 크기 프리셋 *(추가 — 완료)*

- **Publish 프리셋** (Export 탭): 논문 1컬럼 8.3 cm(3.27 in) / 2컬럼 17 cm(6.69 in)
  @300 dpi, 발표 16:9 @150, 보고서 와이드 @200. Copernicus 규정(최소 폭 8 cm)에서 왔다.
  프리셋을 고르면 **'모드별 권장 크기 자동'을 끈다** — 안 그러면 모드를 바꾸는 순간
  논문 폭이 조용히 덮인다. 크기 스핀은 소수 2자리로 넓혔다(3.27을 3.3으로 잘라먹지 않게).
- **EPS 출력 추가** — Copernicus가 EPS/PDF를 1순위로 든다. 실제 파일로 확인:
  `/ArialMT-0 … selectfont` + 글자마다 `glyphshow` = 텍스트가 살아 있다
  (mpl#27328의 "EPS에서 글자 증발"은 Times New Roman 한정이라 우리에겐 안 나타난다).
- **EPS의 대가 둘, 둘 다 알려준다**: ① PostScript엔 알파 채널이 없어 **반투명이
  불투명하게** 찍힌다(에러밴드·야간음영·area/band) → 저장 후 상태줄에 경고.
  ② Type 42 임베딩이라 파일이 크다(같은 그림 PDF 35 KB vs EPS 384 KB).

### M-K. 한글 폰트를 전역으로 걸지 않기 *(추가 — 완료)*

전엔 `font.family = "Malgun Gothic"`이라 **한글이 한 글자도 없는 논문 그림까지**
한글 폰트로 찍혔다(임베딩이 무겁고 "한 패밀리·sans-serif" 권고와 어긋남).

- 이제 `font.family = ["Arial", "<한글폰트>", "DejaVu Sans"]` — matplotlib이 **글리프
  단위로 폴백**해서 ASCII는 Arial, 한글 글자만 한글 폰트로 간다.
- ⚠ **`font.sans-serif` 목록으로는 안 된다**(실측): 그건 "하나를 고르는 후보 목록"이라
  첫 폰트에 없는 글리프는 그냥 □가 된다. `family=['sans-serif']`+`sans-serif=[Arial,
  Malgun]` → 한글 4자 누락, `family=['Arial','Malgun Gothic']` → 누락 0.
- **남은 한계(고칠 수 없어 알려준다)**: 한 라벨에 한글과 `$…$`를 **같이** 쓰면 한글이
  □가 된다. mathtext 엔진이 `$`가 하나라도 있으면 문자열 **전체**를 자기 폰트셋으로
  그리는데 거기엔 한글이 없다(`mathtext.fontset='custom'`으로도 안 고쳐짐).
  한글만·수식만이면 멀쩡하다. → Publish/Preview 때 그런 라벨을 **감지해서 상태줄에
  경고**하고, 라벨 입력칸 툴팁에도 적었다. Publish PDF에서야 발견하는 게 제일 나쁘다.

### M-O. 직접 조작 + 표시 토글 *(추가 — 완료)*

- **곡선을 클릭하면 그 시리즈의 스타일 창**이 열린다(Origin 미니 툴바에서 가져온 것).
  새 팝업을 만들지 않고 **기존 ✏ 창을 그대로 연다** — 목록에서 그 줄을 선택한 뒤
  `_edit_style()`을 호출하므로 편집 경로가 하나로 유지된다. 주석을 찍는 중이면
  클릭을 뺏지 않는다. 막대(BarGraphItem)는 클릭 시그널이 없어 빠진다(목록에서 편집).
- **표시 토글**: 시리즈 목록과 주석 목록에 체크박스. 체크 해제는 **숨김이지 삭제가
  아니다**(헌장 ①의 UI판) — `_series`/`_annots`에 그대로 남고, 설정에도 저장되고,
  다시 켜면 돌아온다. 화면과 Publish에 같은 규칙으로 적용된다.
- **Object Manager를 새 패널로 만들지 않았다.** 그 기능(모든 객체를 보고 켜고 끄기)은
  이미 있는 두 목록에 체크박스를 다는 것으로 끝난다. 별도 패널은 같은 정보를 세 번째
  장소에 복제하는 일이다 — 시리즈·주석 말고 관리할 객체 종류가 더 늘면 그때 만들자.

## 4. 미결 — 조판을 어느 렌더러에 넣나 (결정 보류, 2026-09-21)

M4·M5·M3을 먼저 써보고 정하기로 했다. 선택지를 기록해둔다:

**(A) 화면(pg)에도 조판 그대로**
- 장점: 2×2 패널을 화면에서 직접 보고 만진다. 맛이 제일 좋다.
- 비용: `widget.py`의 절반이 **축 하나(`self.p1`) 전제**로 짜여 있다 —
  `apply_axes`·`pg_label`·`_draw_annotations_pg`·커서·`autoscale`·`vb_right`·
  `update_views`. 전부 "현재 패널"로 일반화해야 하고, **패리티 가드 19개도 패널
  단위로 재작성**해야 한다.

**(B) mpl 전용 조판 + Preview 자동갱신** *(문서 작성 시점의 추천)*
- 화면 pg는 **지금 편집 중인 패널 하나**만 보여준다. Layout 탭에서 셀을 클릭하면
  화면이 그 셀로 바뀌고, 조작법은 지금과 100% 동일.
- 전체 조판은 옆에 띄워둔 Preview가 자동 갱신하며 보여준다.
- **거짓말할 수 없는 이유**: Preview와 Publish는 같은 함수(`_build_publish_fig`,
  `widget.py:1977`)를 쓴다. 미리보기 = 저장 파일.
- 저장소 원칙("화면·출력 스타일 드리프트 금지")은 **패널 하나 안에서 그대로 유지**된다.
  달라지는 건 "몇 개 패널이 한 종이에 있나"뿐 — 그건 스타일이 아니라 배치다.
- 정직한 단점: ① 마우스로 끌어 배치하는 맛은 없다(행/열/비율을 숫자로 지정),
  ② 조판 상태에서 줌·커서 탐색 불가(패널 단위로만), ③ Preview 왕복 —
  그래서 M-P(모덜리스+자동갱신)가 세트로 필요하다.

**판단 기준**: M4·M5·M3을 쓴 뒤 "화면에서 직접 조판하고 싶다"가 실제로 남아 있으면
(A), Preview 창으로 충분하면 (B).
