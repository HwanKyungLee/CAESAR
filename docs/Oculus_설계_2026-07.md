# Oculus 설계 문서 — CAESAR 실시간 관측 시스템

**— ARGUS 우산 아래, 측정이 도는 동안 "지금 정상인가"를 지키는 눈 —**

> *Oculus*(라틴어 "눈") = 계측기 **CAESAR**가 데이터를 떨구는 그 순간에, 장비·광학·농도가
> 정상 범위 안에 있는지 **실시간으로 감시**하는 프로그램. 랩 통합 관측시스템 **ARGUS**(백안의
> 파수꾼) 아래에서, 사후 농도 확정 분석은 *Augur*(이 저장소)가 맡고, 실시간 감시는 *Oculus*가
> 맡는다. Augur가 "나중에 숫자를 맞게 확정하는" 프로그램이라면, Oculus는 "지금 뭔가 잘못되고
> 있으면 즉시 알아채는" 프로그램이다.

작성: 2026-07-23 · 상태: **설계 초안 (코드 미구현)** · 대상 독자: 개발자 + 운용자

---

## 0. 한 장 요약 — Oculus가 하는 일 / 안 하는 일

CAESAR 장비는 raw `.dat` 파일을 주기적으로(현장 기준 약 1시간 단위 파일, 파일 안은 스캔 단위로
누적) 떨군다. 캠페인 중에는 이 파일이 **맞게 쌓이고 있는지**, **거울이 죽지 않았는지**,
**농도가 튀지 않는지**를 사람이 계속 지켜봐야 한다. 지금은 그 감시를 Augur의 📈 Analysis
Monitor 탭을 열어 사람이 눈으로 하거나, R Calibrator를 수동으로 돌려서 한다. Oculus는 이
감시를 **자동·상시**로 돌리는 별도 프로그램이다.

| | **Augur** (사후 분석) | **Oculus** (실시간 감시) |
|---|---|---|
| 목적 | 농도의 **정확한 최종값** 확정 | **지금 정상인가**를 즉시 판단 |
| 시점 | 캠페인 후 / 사람이 RUN | 측정 중 상시 자동 |
| 정확도 vs 속도 | 정확도 우선(전체 재처리, QC 재적용) | 속도·연속성 우선(경량 지표) |
| 산출물 | 확정 농도 시계열, 그림 | 대시보드, 경보(알람), 상태 로그 |
| 사람 개입 | 파라미터 조정·검증 | 무개입 감시, 이상시에만 호출 |

**Oculus가 하지 않는 것**: 최종 농도 확정, QC 정책 결정, 레퍼런스/파장보정 생성. 이런
"확정" 작업은 전부 Augur의 몫이다. Oculus의 농도는 어디까지나 **경향 감시용 근사값**이며,
논문·보고에 쓰는 숫자가 아니다. (경계를 흐리면 두 프로그램을 나눈 의미가 없다.)

## 1. 감시 대상 — 네 개의 눈

운용자가 정한 실시간 감시 대상은 다음 넷이다. 각각 "무엇을 보고", "무엇이 이상 신호이고",
"어떤 데이터에서 나오는지"를 정의한다.

### 1.1 기체 농도 (Concentration)

- **본다**: NO₂ / CHOCHO(글리옥살) / PNs / ANs 등 레퍼런스에 든 기체의 실시간 농도 시계열
  (채널별 CH1=PNs, CH2=ANs, Cold=NO₂).
- **이상 신호**: 물리적으로 불가능한 값(음수 큰 값, 급격한 스파이크), 장시간 flat-line(센서
  고착), 피팅 RMS 급등(피팅 실패 = 농도 신뢰 불가).
- **데이터 출처**: raw `.dat` → α(흡광) → 경량 DOAS 피팅. Augur의 `core/doas_fit.py`
  `DoasFitter`를 그대로 쓰되, shift/squeeze 자유도를 줄이거나 고정해 **속도 우선** 모드로 돈다.

### 1.2 R(반사율) / 거울 상태 (Mirror health)

- **본다**: R(t) 추세, 최근 ZA/He 스캔에서 산출된 R 값, 채널별 R의 절대 수준(0.9998 근처).
- **이상 신호**: R 급락(거울 오염·정렬 틀어짐 → 경로 길이가 무너져 농도 전체가 틀어짐),
  ZA/He 스캔이 예정대로 안 들어옴(교정 시퀀스 중단), R 산출 실패.
- **데이터 출처**: `flag=500`(ZA) / `flag=510`(He) 스캔. Augur의
  `tools/reflectance_calc.py` + `tools/rt_precompute.py`(R(t) knot → `R_<ch>.npz`) 재사용.

### 1.3 장비 헬스 / HK (Housekeeping)

- **본다**: raw `.dat`의 HK 블록(col 6149+) — LED 온도(templed1/2), 오븐 셋포인트(PNs 180 ℃,
  ANs 300 ℃), 캐비티 압력(PNs≈965 mbar, ANs≈915 mbar), 캐비티/분광기 온도, CCD 온도(col 3).
- **이상 신호**: 온도/압력이 정상 밴드 이탈(히터 고장, 가스 누출), CCD 포화(intensity>60000),
  센서 결측(예: tempcell2가 5/27 이전엔 죽어 있었던 것 같은 상황), 노출값 이상.
- **데이터 출처**: `core/raw_parser.py`가 이미 HK 상대 오프셋을 **단일 출처**로 정의해 둠.
  Oculus는 이 파서를 그대로 호출해 HK 열을 뽑고 물리단위로 환산(÷100, ×0.6895 등)만 하면 된다.

### 1.4 raw 유입 감시 (Ingest / liveness)

- **본다**: 감시 폴더에 새 `.dat`가 예정 주기대로 도착하는지, 파일이 커지고 있는지(측정 진행
  중), 마지막 스캔의 타임스탬프(bytepack 시각)와 벽시계의 지연.
- **이상 신호**: 예정 시각을 넘겨 새 파일 없음(DAQ 정지·디스크 풀·네트워크 끊김), 파일 크기가
  안 늘어남(장비 멈춤), 타임스탬프 역행/도약, 헤더만 있고 스캔 없음.
- **데이터 출처**: 파일시스템 watch(`watchdog` 또는 폴링) + `core/raw_parser`의 bytepack 시각
  파싱. **이 감시는 다른 셋의 전제**다 — raw가 안 들어오면 나머지 셋은 볼 데이터가 없으니,
  ingest 경보가 최우선순위(P0)다.

## 2. 아키텍처 개요

Oculus는 하나의 감시 루프를 중심으로 도는 파이프라인이다. Augur가 "사람이 RUN → 배치 처리"인
반면, Oculus는 "파일 이벤트 → 증분 처리 → 대시보드/경보"로 **상시** 돈다.

```
  [CAESAR DAQ]
       │  raw .dat 파일 생성/증분 append
       ▼
  ┌─────────────────┐   파일 이벤트(watchdog/폴링)
  │  Ingest Watcher  │──────────────┐  ← §1.4 감시, liveness 판정
  └─────────────────┘              │
       │ 새 스캔(행) 델타            │
       ▼                          ▼
  ┌─────────────────┐        ┌──────────────┐
  │  raw_parser      │        │ Alert Engine  │  임계값·상태머신
  │ (core, 재사용)   │        │  P0/P1/P2     │  → 알람(소리/색/로그/알림)
  └─────────────────┘        └──────────────┘
       │ 컬럼 분리(spectrum / HK / flag)   ▲
       ├──────────────┬──────────────┐    │ 지표 스트림
       ▼              ▼              ▼    │
  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │ Conc     │  │ R / Mirror│  │ HK Health│
  │ (경량    │  │ (ZA/He   │  │ (밴드    │
  │  DOAS)   │  │  → R(t)) │  │  체크)   │
  └──────────┘  └──────────┘  └──────────┘
       └──────────────┴──────────────┘
                      ▼
             ┌──────────────────┐
             │   Dashboard UI    │  실시간 4-패널 (pyqtgraph)
             │  + 상태 배지·이력  │
             └──────────────────┘
                      │
                      ▼
             상태 로그 (append-only) → 나중에 Augur 확정분석과 대조
```

**핵심 설계 원칙**

1. **증분(incremental)**: 파일 전체를 매번 다시 안 읽는다. 마지막으로 처리한 바이트/행
   오프셋을 기억하고 새로 붙은 스캔만 처리한다(파일당 커서). Augur의 batch와 다른 지점.
2. **읽기 전용 + 무간섭**: Oculus는 raw를 **절대 수정하지 않고**, Augur의 `output/`도 건드리지
   않는다. 자기 상태는 별도 위치(예: `oculus_state/`)에만 쓴다. DAQ가 파일을 쓰는 중에도
   안전하게 읽어야 하므로 부분 읽기·재시도에 견고해야 한다.
3. **경량·연속 우선**: 한 스캔 처리에 실패해도 죽지 않고 다음 스캔으로 넘어간다. 정확도보다
   "끊기지 않는 감시"가 우선. 무거운 재처리는 Augur에 위임.
4. **Augur 코드 재사용, UI는 분리**: 물리·파싱·피팅 로직은 `core/`를 공유(중복 구현 금지),
   실시간 대시보드 UI만 새로 만든다.

## 3. Augur 코드 재사용 매핑

Oculus는 바닥부터 짜지 않는다. 이미 검증된 `core/`·`tools/`를 그대로 호출한다.

| Oculus 기능 | 재사용할 Augur 자산 | 비고 |
|---|---|---|
| raw 컬럼/HK/flag 파싱 | `core/raw_parser.py` | **단일 출처**. 열 인덱스 하드코딩 금지, 반드시 경유 |
| bytepack 타임스탬프 | `core/raw_parser.py` (col0·col1) | ingest 지연·역행 판정 |
| α(흡광) 생성 | `core/data_io.py`, `gui/ui_alpha_gen.py` 로직 | 경량 모드로 감쌈 |
| 경량 DOAS 피팅 | `core/doas_fit.py` `DoasFitter`, `core/engine.py` | shift/squeeze 고정·자유도 축소 옵션 |
| R 계산 | `tools/reflectance_calc.py` (Rayleigh+CEAS) | ZA/He 스캔 입력 |
| R(t) 추세 | `tools/rt_precompute.py`, `tools/r_trend_monitor.py` | knot → `R_<ch>.npz` |
| Rayleigh 물리 / 칼만 | `core/physics.py` (`RayleighPhysics`, `KalmanTracker`) | 스파이크 완화·평활 |
| 실시간 플롯 위젯 | `gui/monitor_widget.py` `MonitorWidget` | anti-flicker 패턴 참고/부분 재사용 |
| 산출물 상태 점검 | `core/health_checks.py`, `core/step_guard.py` | 밴드/스텝 판정 로직 참고 |
| 경로 규약 | `core/paths.py` | `REPO_ROOT` 기준. Oculus 상태는 별도 폴더 |

> 이미 `gui/worker.py` `AnalysisWorker`가 `result_ready(dict,int)`,
> `trend_update(dict)`, `plot_update(...)`, `r_curve_update(...)` 같은 신호로 스캔 단위
> 결과를 흘려보내는 구조라, Oculus의 증분 루프는 이 신호 스키마를 거의 그대로 재사용할 수 있다.

## 4. 데이터 흐름 (한 스캔의 일생)

1. **Watcher**가 감시 폴더에서 `foo.dat` 변경 이벤트를 받는다(또는 N초 폴링).
2. 파일별 **커서**(마지막 처리 오프셋)를 확인해 새로 붙은 행만 `raw_parser`로 읽는다.
3. 각 새 행에서 **flag**를 본다:
   - `flag=1`(대기 측정) → spectrum을 경량 DOAS로 피팅 → **농도 지표**(§1.1) + shift/RMS.
   - `flag=500/510`(ZA/He) → R 산출 파이프라인에 투입 → **R 지표**(§1.2).
   - 모든 행 → HK 블록 환산 → **헬스 지표**(§1.3).
4. bytepack 시각 vs 벽시계 → **ingest 지연**(§1.4).
5. 각 지표를 **Alert Engine**에 넣어 임계값·상태머신으로 P0/P1/P2 판정.
6. 대시보드 갱신(throttle ~150 ms, `monitor_widget`의 anti-flicker 패턴) + 상태 로그 append.
7. 이상시 알람(색·소리·데스크톱 알림; 원격이면 푸시/웹훅 선택).

## 5. 경보 등급과 임계값(초안)

| 등급 | 뜻 | 예시 조건 | 동작 |
|---|---|---|---|
| **P0** | 측정 자체가 멈춤/무의미 | 예정 주기 지나도 새 파일 없음, 파일 크기 정지, CCD 전 채널 포화, R 산출 연속 실패 | 즉시 알람 + 로그 강조 |
| **P1** | 데이터는 오나 품질 위험 | R 급락(추세 대비 임계 초과), 오븐/압력 밴드 이탈, RMS 급등, 농도 물리 이탈 | 경고 알람 |
| **P2** | 주의·관찰 | 완만한 R 드리프트, 센서 1개 결측, 경미한 shift 증가 | 배지 색만, 로그 |

임계값은 **캠페인별로 다르다**(장비 상태·목표 기체가 다름). 그래서 임계값은 코드 상수가 아니라
**설정 파일**(예: `oculus/thresholds/<campaign>.json`)로 빼고, 대시보드에서 조정 가능해야
한다. 초기값은 `core/raw_parser.py`에 기록된 정상 밴드(오븐 180/300 ℃, 압력 965/915 mbar,
포화 60000 등)와 `core/step_guard.py`의 스텝 임계에서 가져온다.

## 6. 폴더 구조 제안

Augur 저장소 안에 `oculus/` 패키지로 두되(코어 공유가 쉬움), 진입점은 독립시킨다.
필요하면 나중에 별도 저장소로 분리 가능하도록 `core/` 의존만 두고 `gui/`에는 최소 의존.

```
CAESAR/
├── oculus/                       ← 실시간 감시 프로그램 (새 패키지)
│   ├── __init__.py
│   ├── run_oculus.py             ← 진입점 (python -m oculus 또는 oculus/run_oculus.py)
│   ├── watcher.py                ← Ingest Watcher (watchdog/폴링 + 파일별 커서) §1.4
│   ├── ingest_cursor.py          ← 파일별 처리 오프셋 저장/복원 (재시작 견고성)
│   ├── monitors/
│   │   ├── conc_monitor.py       ← §1.1 경량 DOAS (core.doas_fit 재사용)
│   │   ├── r_monitor.py          ← §1.2 R/거울 (tools.reflectance_calc 재사용)
│   │   ├── hk_monitor.py         ← §1.3 HK 밴드 체크 (core.raw_parser 재사용)
│   │   └── liveness_monitor.py   ← §1.4 유입 지연/정지 판정
│   ├── alert_engine.py           ← 임계값·상태머신·등급(P0/P1/P2)
│   ├── notifier.py               ← 알람 채널(소리/색/데스크톱/웹훅) 추상화
│   ├── dashboard/
│   │   └── dashboard_window.py   ← 실시간 4-패널 UI (monitor_widget 패턴 재사용)
│   ├── thresholds/
│   │   └── default.json          ← 임계값 설정(캠페인별 오버라이드)
│   └── state_log.py              ← append-only 상태 로그 (나중 Augur 대조용)
│
├── oculus_state/                 ← 런타임 산출물 (커서·로그·경보 이력) [.gitignore]
└── ...(기존 Augur 트리)
```

> `oculus_state/`는 머신별 재생성 산출물이므로 `output/`·`logs/`처럼 `.gitignore`에 넣는다.
> Oculus는 raw와 Augur `output/`을 읽기만 하고 쓰지 않는다(§2 원칙 2).

## 7. 단계별 로드맵

정확도보다 "돌아가는 감시"를 먼저 세우고 단계적으로 눈을 늘린다.

- **M0 — 골격 & 유입 감시 (MVP)**: `watcher.py` + `liveness_monitor.py` + 최소 대시보드.
  raw가 들어오는지/멈췄는지만 본다. §1.4 P0 경보 하나로도 현장에서 즉시 유용.
- **M1 — HK 헬스**: `hk_monitor.py`. `raw_parser` HK 환산 + 밴드 체크. 온도/압력/포화 배지.
  (피팅 없이 되므로 두 번째로 싸고 가치 큼.)
- **M2 — R / 거울**: `r_monitor.py`. ZA/He 스캔에서 R 산출·추세. `rt_precompute` 재사용.
- **M3 — 농도 경량 피팅**: `conc_monitor.py`. `DoasFitter` 속도 모드. 가장 무겁고 마지막.
- **M4 — 경보 고도화 & 원격**: 상태머신 정교화, 웹훅/푸시 알림, 임계값 캠페인 프로필.

각 단계는 그 자체로 배포 가능(독립적으로 유용)해야 한다.

## 8. 미해결 질문 (착수 전 확정 필요)

1. **실행 환경**: 현장 DAQ(Windows)에서 Augur와 **동시에** 돌리나, 아니면 별도 감시 PC인가?
   (동일 PC면 CPU 경쟁 → M3 피팅 부하 조절 필요.)
2. **파일 주기의 정확한 정의**: "1시간 파일"인가 "1초 스캔이 1시간 파일에 누적"인가 —
   liveness 임계(예정 도착 시각)를 정하려면 확정 필요. (README는 1시간 파일, 소개문서는
   1초 스캔 언급 → 실제 현장 규약 확인.)
3. **알람 도달 경로**: 현장에서 소리/화면이면 충분한가, 원격(당직자 휴대폰 푸시/메신저)까지
   필요한가? → `notifier.py` 설계가 갈린다.
4. **경량 피팅 허용 오차**: Oculus 농도가 Augur 확정값과 몇 % 이내면 "경향 감시로 충분"인가?
   (shift/squeeze 고정 시 오차 상한 실측 필요.)
5. **Cold/Hot 동시 감시**: 두 장비를 한 Oculus 인스턴스가 보나, 인스턴스를 나누나?
