# Oculus 설계 문서 — CAESAR 실시간 관측 시스템

**— ARGUS 우산 아래, 측정이 도는 동안 "지금 정상인가"를 지키는 눈 —**

> *Oculus*(라틴어 "눈") = 계측기 **CAESAR**가 데이터를 떨구는 그 순간에, 장비·광학·농도가
> 정상 범위 안에 있는지 **실시간으로 감시**하는 프로그램. 랩 통합 관측시스템 **ARGUS**(백안의
> 파수꾼) 아래에서, 사후 농도 확정 분석은 *Augur*(이 저장소)가 맡고, 실시간 감시는 *Oculus*가
> 맡는다. Augur가 "나중에 숫자를 맞게 확정하는" 프로그램이라면, Oculus는 "지금 뭔가 잘못되고
> 있으면 즉시 알아채는" 프로그램이다.

작성: 2026-07-23 · 개정: 2026-07-23 (운용 결정 반영) · 상태: **설계 초안 (코드 미구현)** · 대상 독자: 개발자 + 운용자

## 0-A. 확정 결정 (2026-07-23) — 착수 전 합의된 방향

아래는 운용자와 합의해 확정한 설계 전제다. 이후 절들은 이 결정을 따른다.

1. **실행 토폴로지**: Oculus는 **DAQ PC에서 LabVIEW와 나란히** 도는 프로그램이다(raw가 쓰이는
   그 컴퓨터에서 바로 읽음). 농도 확정 분석(Augur)은 **별도 컴퓨터에서 피팅만** 따로 돌린다.
   → Oculus는 "측정 현장에 붙어 사는 감시자", Augur는 "원격/사후 분석가".
2. **데이터 케이던스**: raw는 **1시간짜리 파일** 안에 **매 1초마다 스캔 한 줄**이 append된다.
   즉 정상 상태의 기대는 "약 1초마다 새 행, 약 1시간마다 새 파일 rollover". liveness 임계의
   1차 기준값이 여기서 나온다(정확한 주기는 추후 LabVIEW 코드로 확정).
3. **알람의 목적**: 알람은 "피팅이 이상하다"가 아니라 **운영 사고**를 잡는 것이 핵심이다 —
   *데이터는 계속 쌓이는데 과학이 조용히 망가지는* 상황(DAQ 정지, 거울 R 붕괴, 오븐/압력
   이탈, CCD 포화). 이런 건 LabVIEW 수집 화면만 봐선 안 보인다. 초기 채널은 **화면 색 배지 +
   소리 + append 로그**로 충분하고, 원격 푸시는 무인 야간운용용으로 나중에.
4. **경량 피팅 허용도**: 실시간 농도는 정확값이 아니어도 **"믿고 추세를 볼 수 있는 수준"**이면
   된다. 하드 임계(90% 등)를 미리 못박지 않고, **Augur 확정값에 겹쳐 사후 검증**해 경험적으로
   정한다. 목적이 "3 ppb인지 300 ppb인지 / 스파이크·flat-line"을 잡는 것이므로 절대정확도보다
   자릿수·추세 일치가 기준.
5. **단일 인스턴스·전 채널**: 한 Oculus 인스턴스가 그 장비의 **모든 채널**을 함께 본다
   (채널을 인스턴스로 쪼개지 않음).
6. **★ 채널 명명 하드코딩 금지 (범용 리더 원칙)**: `Cold`/`Hot`/`PNs`/`ANs` 같은 이름·레이아웃은
   **채널 구성·캐비티 선택에 따라 매번 달라진다**. Oculus는 특정 구성에 박제되지 않고, **어떤
   CAESAR가 뱉는 raw든 읽어서** 모니터링해야 한다. → 채널 정체성은 **설정 프로파일 + 자동탐지**
   로 다루고, `Cold`/`PNs` 같은 라벨은 로직이 아니라 **표시용 메타데이터**로만 쓴다. (§2-A 참조)

## 0. 한 장 요약 — Oculus가 하는 일 / 안 하는 일

CAESAR 장비는 raw `.dat` 파일을 주기적으로(현장 기준 약 1시간 단위 파일, 파일 안은 스캔 단위로
누적) 떨군다. 캠페인 중에는 이 파일이 **맞게 쌓이고 있는지**, **거울이 죽지 않았는지**,
**농도가 튀지 않는지**를 사람이 계속 지켜봐야 한다. 지금은 그 감시를 Augur의 📈 Analysis
Monitor 탭을 열어 사람이 눈으로 하거나, R Calibrator를 수동으로 돌려서 한다. Oculus는 이
감시를 **자동·상시**로 돌리는 별도 프로그램이다.

| | **Augur** (사후 분석) | **Oculus** (실시간 감시) |
|---|---|---|
| 목적 | 농도의 **정확한 최종값** 확정 | **지금 정상인가**를 즉시 판단 |
| 시점 | 캠페인 후 / 사람이 RUN | 측정 중 상시 자동 |
| 정확도 vs 속도 | 정확도 우선(전체 재처리, QC 재적용) | 속도·연속성 우선(경량 지표) |
| 산출물 | 확정 농도 시계열, 그림 | 대시보드, 경보(알람), 상태 로그 |
| 사람 개입 | 파라미터 조정·검증 | 무개입 감시, 이상시에만 호출 |

**Oculus가 하지 않는 것**: 최종 농도 확정, QC 정책 결정, 레퍼런스/파장보정 생성. 이런
"확정" 작업은 전부 Augur의 몫이다. Oculus의 농도는 어디까지나 **경향 감시용 근사값**이며,
논문·보고에 쓰는 숫자가 아니다. (경계를 흐리면 두 프로그램을 나눈 의미가 없다.)

## 1. 감시 대상 — 네 개의 눈

운용자가 정한 실시간 감시 대상은 다음 넷이다. 각각 "무엇을 보고", "무엇이 이상 신호이고",
"어떤 데이터에서 나오는지"를 정의한다.

### 1.1 기체 농도 (Concentration)

- **본다**: 활성 채널마다, 그 채널에 배정된 레퍼런스 기체들의 실시간 농도 시계열. 어떤 기체가
  어느 채널인지는 **프로파일이 정하거나 자동탐지**하며(§2-A), 종·채널 이름을 코드에 박지 않는다.
- **이상 신호**: 물리적으로 불가능한 값(음수 큰 값, 급격한 스파이크), 장시간 flat-line(센서
  고착), 피팅 RMS 급등(피팅 실패 = 농도 신뢰 불가).
- **데이터 출처**: raw `.dat` → α(흡광) → 경량 DOAS 피팅. Augur의 `core/doas_fit.py`
  `DoasFitter`를 그대로 쓰되, shift/squeeze 자유도를 줄이거나 고정해 **속도 우선** 모드로 돈다.
- **허용도(§0-A.4)**: 정확값이 아니라 자릿수·추세를 믿을 수 있으면 충분. 하드 임계 대신 Augur
  확정값과 사후 겹쳐보기로 경험적 검증.

### 1.2 R(반사율) / 거울 상태 (Mirror health)

- **본다**: 활성 채널마다 R(t) 추세, 최근 ZA/He 스캔에서 산출된 R 값, R의 절대 수준
  (고반사 거울이면 0.9998 근처지만, 정상 밴드는 프로파일이 정한다 — §2-A).
- **이상 신호**: R 급락(거울 오염·정렬 틀어짐 → 경로 길이가 무너져 농도 전체가 틀어짐),
  ZA/He 스캔이 예정대로 안 들어옴(교정 시퀀스 중단), R 산출 실패.
- **데이터 출처**: ZA/He 상태 flag(현재 CAESAR는 500/510이나, flag 규약도 프로파일에서 읽는다)
  스캔. Augur의 `tools/reflectance_calc.py` + `tools/rt_precompute.py`(R(t) knot → `R_<ch>.npz`) 재사용.

### 1.3 장비 헬스 / HK (Housekeeping)

- **본다**: raw `.dat`의 HK 블록 — LED 온도, 오븐 셋포인트, 캐비티 압력, 캐비티/분광기 온도,
  CCD 온도 등. **어느 열이 무엇이고 단위·정상밴드가 얼마인지는 프로파일이 정의**한다(§2-A).
  예컨대 현재 CAESAR는 오븐 180/300 ℃, 압력 965/915 mbar, 포화 60000 등이지만 이 값들은
  프로파일 상수이지 코드 상수가 아니다.
- **이상 신호**: 온도/압력이 정상 밴드 이탈(히터 고장, 가스 누출), CCD 포화, 센서 결측
  (예: 특정 tempcell이 어느 시점 이전엔 죽어 있던 상황), 노출값 이상.
- **데이터 출처**: 프로파일의 HK 열 지도 → 물리단위 환산(÷100, ×0.6895 등). 현재 CAESAR
  레이아웃은 `core/raw_parser.py`가 이미 문서화해 두었으므로 **기본 프로파일의 출발점**으로 쓴다.

### 1.4 raw 유입 감시 (Ingest / liveness)

- **본다**: 정상 케이던스(§0-A.2)는 **약 1초마다 새 스캔 행 append, 약 1시간마다 새 파일
  rollover**. 현재 파일이 계속 커지는지, 마지막 스캔의 bytepack 시각과 벽시계의 지연, 파일
  rollover가 제때 일어나는지를 본다.
- **이상 신호**: 초 단위로 행이 더 안 붙음(=측정 정지, 가장 흔하고 치명적), 예정 시각 지나도
  새 파일 rollover 없음, 파일 크기 정지, 타임스탬프 역행/도약, 헤더만 있고 스캔 없음, 디스크 풀.
- **데이터 출처**: 파일시스템 watch(`watchdog` 또는 폴링) + `core/raw_parser`의 bytepack 시각
  파싱. **이 감시는 다른 셋의 전제**다 — raw가 안 들어오면 나머지 셋은 볼 데이터가 없으니,
  ingest 경보가 최우선순위(P0)다.

## 2. 아키텍처 개요

Oculus는 하나의 감시 루프를 중심으로 도는 파이프라인이다. Augur가 "사람이 RUN → 배치 처리"인
반면, Oculus는 "파일 이벤트 → 증분 처리 → 대시보드/경보"로 **상시** 돈다.

```
  [CAESAR DAQ]
       │  raw .dat 파일 생성/증분 append
       ▼
  ┌─────────────────┐   파일 이벤트(watchdog/폴링)
  │  Ingest Watcher  │──────────────┐  ← §1.4 감시, liveness 판정
  └─────────────────┘              │
       │ 새 스캔(행) 델타            │
       ▼                          ▼
  ┌─────────────────┐        ┌──────────────┐
  │  raw_parser      │        │ Alert Engine  │  임계값·상태머신
  │ (core, 재사용)   │        │  P0/P1/P2     │  → 알람(소리/색/로그/알림)
  └─────────────────┘        └──────────────┘
       │ 컬럼 분리(spectrum / HK / flag)   ▲
       ├──────────────┬──────────────┐    │ 지표 스트림
       ▼              ▼              ▼    │
  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │ Conc     │  │ R / Mirror│  │ HK Health│
  │ (경량    │  │ (ZA/He   │  │ (밴드    │
  │  DOAS)   │  │  → R(t)) │  │  체크)   │
  └──────────┘  └──────────┘  └──────────┘
       └──────────────┴──────────────┘
                      ▼
             ┌──────────────────┐
             │   Dashboard UI    │  실시간 4-패널 (pyqtgraph)
             │  + 상태 배지·이력  │
             └──────────────────┘
                      │
                      ▼
             상태 로그 (append-only) → 나중에 Augur 확정분석과 대조
```

**핵심 설계 원칙**

1. **증분(incremental)**: 파일 전체를 매번 다시 안 읽는다. 마지막으로 처리한 바이트/행
   오프셋을 기억하고 새로 붙은 스캔만 처리한다(파일당 커서). Augur의 batch와 다른 지점.
2. **읽기 전용 + 무간섭**: Oculus는 raw를 **절대 수정하지 않고**, Augur의 `output/`도 건드리지
   않는다. 자기 상태는 별도 위치(예: `oculus_state/`)에만 쓴다. DAQ가 파일을 쓰는 중에도
   안전하게 읽어야 하므로 부분 읽기·재시도에 견고해야 한다.
3. **경량·연속 우선**: 한 스캔 처리에 실패해도 죽지 않고 다음 스캔으로 넘어간다. 정확도보다
   "끊기지 않는 감시"가 우선. 무거운 재처리는 Augur에 위임.
4. **Augur 코드 재사용, UI는 분리**: 물리·파싱·피팅 로직은 `core/`를 공유(중복 구현 금지),
   실시간 대시보드 UI만 새로 만든다.
5. **프로파일 주도 · 채널 무관(§0-A.6)**: 채널 개수·역할·이름·HK 열지도·flag 규약을 코드에
   박지 않고 **인스트루먼트 프로파일**에서 읽는다. 어떤 CAESAR 구성이 와도 프로파일만 바꾸면
   돈다.

## 2-A. 인스트루먼트 프로파일 — 범용 리더의 심장

Oculus가 "특정 장비 구성에 박제되지 않고 어떤 CAESAR raw든 읽는다"(§0-A.6)를 실현하는 장치가
**인스트루먼트 프로파일**이다. `Cold`/`Hot`/`PNs`/`ANs`처럼 구성마다 바뀌는 것들을 코드에서
빼내 캠페인별 설정 파일(예: `oculus/profiles/<campaign>.json`)로 옮긴다.

> **구현 상태**: 프로파일 스키마·예제·로더가 이미 있다 —
> `oculus/profiles/_schema.json`(JSON Schema, draft 2020-12로 검증됨),
> `oculus/profiles/caesar_cold.example.json`(6179열·NO₂ 1채널),
> `oculus/profiles/caesar_hot.example.json`(6181열·PNs+ANs 2채널),
> 필드 설명은 `oculus/profiles/README.md`. 값의 출처는 `core/raw_parser.py`의
> VALUE-INSPECTION 기록.
>
> 로더는 `oculus/profile.py` — 프로파일 로드·검증(jsonschema 있으면 스키마, 없으면
> 구조검사 폴백), `ProfileSet.route()`로 파일→프로파일 라우팅(열수 1차·파일명 보조),
> raw 한 행에서 시각(bytepack)·flag 역할·채널 스펙트럼·HK 물리값·포화·채널 자동탐지를
> 뽑는 헬퍼를 제공한다. 단위테스트 `oculus/test_profile.py`(36항목, CI 등록)로 검증.

**프로파일이 정의하는 것**

- **헤더 규약**: 타임스탬프(col 0·1 bytepack), exposure, CCD temp, state flag 열 위치.
  (이 앞부분은 CAESAR 공통이라 기본값이 안정적.)
- **채널 지도**: 채널 개수, 각 채널의 스펙트럼 열 범위(예: 2048 폭 블록), **표시 라벨**
  (`Cold`/`PNs` 등은 여기서만 사는 문자열일 뿐 로직이 아니다), 채널별 파장보정·레퍼런스 매핑.
- **HK 지도**: 어느 HK 열이 무엇인지 + 단위 환산(÷100, ×0.6895 …) + **정상 밴드**(경보 임계).
- **flag 규약**: 대기/ZA/He/대기전이 등의 flag 숫자(현재 1 / 500 / 510 …이나 프로파일 값).

**자동탐지(프로파일 보강)**: 프로파일이 없거나 부분적일 때, 첫 몇 스캔의 **블록별 최대값
휴리스틱**으로 활성 채널을 발견한다 — 신호 블록은 max ≈ 3만~5만, 노이즈 블록은 max ≈ 700~900
(이 임계 근거는 `core/raw_parser.py`의 VALUE-INSPECTION 기록). 이렇게 "읽고 나서 구조를
알아내는" 경로를 두면 새 구성에도 무설정으로 최소 감시가 가능하다.

> **함의**: 현재 `core/raw_parser.py`는 2026 여수 Cold/Hot 레이아웃을 **하드코딩**한다(단일
> 출처로서 옳다). Oculus는 그 위에 **프로파일 주도 인제스트 계층**을 둔다 — 기본 프로파일은
> raw_parser의 기록에서 생성하되, 열 인덱스를 코드로 가정하지 않는다. (이 일반화가 잘 되면
> 나중에 raw_parser 자체를 프로파일 기반으로 확장해 Augur에도 역수혈할 여지가 있다.)

## 3. Augur 코드 재사용 매핑

Oculus는 바닥부터 짜지 않는다. 이미 검증된 `core/`·`tools/`를 그대로 호출한다.

| Oculus 기능 | 재사용할 Augur 자산 | 비고 |
|---|---|---|
| raw 컬럼/HK/flag 파싱 | `core/raw_parser.py` | 현재 레이아웃 기록 → **기본 프로파일의 씨앗**. Oculus는 프로파일 계층으로 감싸 열 인덱스를 코드로 가정하지 않음(§2-A) |
| bytepack 타임스탬프 | `core/raw_parser.py` (col0·col1) | ingest 지연·역행 판정 |
| α(흡광) 생성 | `core/data_io.py`, `gui/ui_alpha_gen.py` 로직 | 경량 모드로 감쌈 |
| 경량 DOAS 피팅 | `core/doas_fit.py` `DoasFitter`, `core/engine.py` | shift/squeeze 고정·자유도 축소 옵션 |
| R 계산 | `tools/reflectance_calc.py` (Rayleigh+CEAS) | ZA/He 스캔 입력 |
| R(t) 추세 | `tools/rt_precompute.py`, `tools/r_trend_monitor.py` | knot → `R_<ch>.npz` |
| Rayleigh 물리 / 칼만 | `core/physics.py` (`RayleighPhysics`, `KalmanTracker`) | 스파이크 완화·평활 |
| 실시간 플롯 위젯 | `gui/monitor_widget.py` `MonitorWidget` | anti-flicker 패턴 참고/부분 재사용 |
| 산출물 상태 점검 | `core/health_checks.py`, `core/step_guard.py` | 밴드/스텝 판정 로직 참고 |
| 경로 규약 | `core/paths.py` | `REPO_ROOT` 기준. Oculus 상태는 별도 폴더 |

> 이미 `gui/worker.py` `AnalysisWorker`가 `result_ready(dict,int)`,
> `trend_update(dict)`, `plot_update(...)`, `r_curve_update(...)` 같은 신호로 스캔 단위
> 결과를 흘려보내는 구조라, Oculus의 증분 루프는 이 신호 스키마를 거의 그대로 재사용할 수 있다.

## 4. 데이터 흐름 (한 스캔의 일생)

1. **Watcher**가 감시 폴더에서 `foo.dat` 변경 이벤트를 받는다(또는 N초 폴링).
2. 파일별 **커서**(마지막 처리 오프셋)를 확인해 새로 붙은 행만 `raw_parser`로 읽는다.
3. 각 새 행에서 **flag**(프로파일의 flag 규약)를 본다:
   - 대기 측정 flag → spectrum을 경량 DOAS로 피팅 → **농도 지표**(§1.1) + shift/RMS.
   - ZA/He flag → R 산출 파이프라인에 투입 → **R 지표**(§1.2).
   - 모든 행 → HK 블록 환산(프로파일 HK 지도) → **헬스 지표**(§1.3).
4. bytepack 시각 vs 벽시계, 그리고 직전 행과의 초 단위 간격 → **ingest 지연/정지**(§1.4).
5. 각 지표를 **Alert Engine**에 넣어 임계값·상태머신으로 P0/P1/P2 판정.
6. 대시보드 갱신(throttle ~150 ms, `monitor_widget`의 anti-flicker 패턴) + 상태 로그 append.
7. 이상시 알람 — 초기엔 **화면 색 배지 + 소리 + append 로그**, 원격 푸시는 무인운용용으로 나중(§0-A.3).

## 5. 경보 등급과 임계값(초안)

**알람의 목적(§0-A.3)**: "피팅이 이상하다"가 아니라 **데이터는 쌓이는데 과학이 조용히 망가지는
운영 사고**를 잡는 것. LabVIEW 수집 화면만 봐선 안 보이는 것들(측정 정지, R 붕괴, 오븐/압력
이탈, CCD 포화)이 1순위다. 피팅 품질(RMS) 경보는 부차적 옵션.

| 등급 | 뜻 | 예시 조건 | 동작 |
|---|---|---|---|
| **P0** | 측정 자체가 멈춤/무의미 | 초 단위로 새 행 안 붙음(측정 정지), 파일 크기 정지, 디스크 풀, 전 채널 CCD 포화, R 산출 연속 실패 | 즉시 알람(소리+빨강 배지) + 로그 강조 |
| **P1** | 데이터는 오나 품질 위험 | R 급락(추세 대비 임계 초과), 오븐/압력 밴드 이탈, RMS 급등, 농도 물리 이탈 | 경고 알람 |
| **P2** | 주의·관찰 | 완만한 R 드리프트, 센서 1개 결측, 경미한 shift 증가 | 배지 색만, 로그 |

임계값은 **캠페인·장비 구성별로 다르므로** 코드 상수가 아니라 **인스트루먼트 프로파일**(§2-A)의
정상 밴드에서 온다(HK 밴드·flag 규약과 한 파일에 묶임). 대시보드에서 조정 가능해야 한다.
현재 CAESAR 초기값(오븐 180/300 ℃, 압력 965/915 mbar, 포화 60000 등)은 `core/raw_parser.py`와
`core/step_guard.py` 기록에서 기본 프로파일로 가져온다.

## 6. 폴더 구조 제안

Augur 저장소 안에 `oculus/` 패키지로 두되(코어 공유가 쉬움), 진입점은 독립시킨다.
필요하면 나중에 별도 저장소로 분리 가능하도록 `core/` 의존만 두고 `gui/`에는 최소 의존.

```
CAESAR/
├── oculus/                       ← 실시간 감시 프로그램 (새 패키지)
│   ├── __init__.py
│   ├── run_oculus.py             ← 진입점 (python -m oculus 또는 oculus/run_oculus.py)
│   ├── watcher.py                ← Ingest Watcher (watchdog/폴링 + 파일별 커서) §1.4
│   ├── ingest_cursor.py          ← 파일별 처리 오프셋 저장/복원 (재시작 견고성)
│   ├── monitors/
│   │   ├── conc_monitor.py       ← §1.1 경량 DOAS (core.doas_fit 재사용)
│   │   ├── r_monitor.py          ← §1.2 R/거울 (tools.reflectance_calc 재사용)
│   │   ├── hk_monitor.py         ← §1.3 HK 밴드 체크 (core.raw_parser 재사용)
│   │   └── liveness_monitor.py   ← §1.4 유입 지연/정지 판정
│   ├── profile.py                ← 인스트루먼트 프로파일 로더 + 자동탐지 (§2-A 범용 리더)
│   ├── profiles/
│   │   └── caesar_default.json   ← 기본 프로파일(채널지도·HK지도·flag규약·정상밴드)
│   │                                 캠페인별 오버라이드로 복제. Cold/Hot 등은 여기 라벨로만
│   ├── alert_engine.py           ← 임계값(프로파일 밴드)·상태머신·등급(P0/P1/P2)
│   ├── notifier.py               ← 알람 채널(색/소리/로그, 나중에 데스크톱/웹훅) 추상화
│   ├── dashboard/
│   │   └── dashboard_window.py   ← 실시간 4-패널 UI, 전 채널 한 화면 (monitor_widget 패턴)
│   └── state_log.py              ← append-only 상태 로그 (나중 Augur 대조용)
│
├── oculus_state/                 ← 런타임 산출물 (커서·로그·경보 이력) [.gitignore]
└── ...(기존 Augur 트리)
```

> `oculus_state/`는 머신별 재생성 산출물이므로 `output/`·`logs/`처럼 `.gitignore`에 넣는다.
> Oculus는 raw와 Augur `output/`을 읽기만 하고 쓰지 않는다(§2 원칙 2).

전면 재작업이 되므로 첫 단계에 포함**한다.

## 8. 결정 완료 / 남은 확인

**§0-A에서 확정됨** (2026-07-23):

1. 실행 환경 → DAQ PC에서 LabVIEW와 동시, Augur는 별도 PC (§0-A.1).
2. 파일 주기 → 1시간 파일 + 1초마다 스캔 행 append (§0-A.2).
3. 알람 경로 → 초기엔 화면/소리/로그, 원격은 나중(무인용) (§0-A.3).
4. 경량 피팅 허용 → 하드 임계 없이 추세·자릿수 신뢰 + Augur 사후 검증 (§0-A.4).
5. 채널 감시 → 한 인스턴스가 전 채널, 명명 하드코딩 금지·프로파일 주도 (§0-A.5·6).

**착수 후 실측·확인이 필요한 것** (설계를 막지는 않음):

- **LabVIEW 실제 케이던스 확정**: 정확한 스캔 간격/파일 rollover 주기. → liveness 임계 미세조정.
  (프로파일 값으로 두므로 코드 변경 없이 반영.)
- **동시 실행 CPU 예산**: 같은 PC에서 LabVIEW와 공존하므로 M3 피팅이 DAQ를 방해하지 않도록
  스로틀/우선순위 필요(`worker.py`가 BLAS 스레드·코어 절반 제한을 이미 하는 패턴 참고).
- **경량 피팅 오차 상한 실측**: shift/squeeze 고정 시 Augur 대비 편차를 첫 데이터로 측정.
- **R 모니터 캐비티 HK 매핑·임계값 확인** (M2 신규): 프로파일의 `reflectance.cavity_temp_hk`가
  ANs=`oven_ans_setpoint`(300℃)·PNs=`oven_pns_setpoint`(180℃)로 되어 있는데, 이건
  `core/raw_parser.py` 문서 주석에서 유추한 것 — 실제 캐비티 가스온도가 오븐 셋포인트와
  같은지 계기 담당자 확인 필요. `warn_drop`/`alarm_drop`(현재 2e-5/1e-4)도 실측 전 임시값.
  R이 0.9999 부근에서 매우 비선형(테스트로 확인: 1e-4 하락만으로도 He/ZA contrast가
  유효밴드 경계에 근접)이라 실측 튜닝이 특히 중요하다.
