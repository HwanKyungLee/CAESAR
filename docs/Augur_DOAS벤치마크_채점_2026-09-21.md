## 0. 무엇과 무엇을 비교했나 — 먼저 읽을 것

비교 대상은 벤치마크 패키지에 같이 들어 있는 **`baseline.py` 하나**다.
**QDOAS 도 DOASIS 도 아니다.** README 의 자기 설명:

> 프로파일된 shift 탐색 + 열 정규화 선형해 + 공분산 기반 불확도.
> **권장 구현이 아니며**, 형식을 고정하고 넘어설 대상을 주려는 것.

즉 교과서적 최소 구현이고, 벤치마크를 만든 쪽이 같이 쓴 것이다. 독립적인 제3자

### 2-A. v3 에서 바뀐 것 — A 군 FAIL 은 벤치마크 결함이었다

v3 에서 Augur 3차 보간이 A 군 최대 상대오차 **2.44e-3 (FAIL)** 이었다. 원인은
shift 가 아니라 **squeeze** 였다. A 군이 `squeeze = 1.002` 로 만들어져 있어서,
정수 shift 라도 `p'` 가 전 픽셀에서 비정수가 되고 **모든 구현이 보간을 탄다.**
생성기가 선형보간이므로 선형 구현이 이긴다 — 정확도가 아니라 **보간자 일치**를
재고 있었다.

v4 가 `squeeze = 1.000` 으로 고쳤다. 이제 `p' = p + d` 가 정수 격자에 떨어져
어떤 보간자든 정확하다. **Augur 의 A 군 FAIL 은 사라졌다(0.0 PASS).**

| | v3 (squeeze 1.002) | **v4 (squeeze 1.000)** |
|---|---|---|
| Augur 3차(운영) | 2.44e-3 ❌ | **0.0 ✅** |
| Augur 선형 | 0.0 ✅ | 0.0 ✅ |

⚠ **v3 기준으로 쓴 "보간 차수가 NO₂ 를 0.24 % 움직인다 → §4 새 예산 항" 은
철회한다.** 그 0.24 % 는 선형 진값 대비 3차의 불일치였고, 진값 쪽이 물리가
아니었다. 올바른 값은 §3-C 에 있다.

## 3. 읽는 법 — 진단이 기여다

### 3-A. 두 독립 구현이 **같은 방향으로** 실패한다

이게 논문의 논지다.

| 실패 양상 | 기준 구현 | Augur |
|---|---|---|
| AR(1) 상관 잔차에서 보고 불확도 과소 | 1.57배 | 1.65배 |
| 모델 불일치 편향 / 보고 σ | 11.2배 | 9.8배 |
| 창을 바꾸면 답이 바뀜(전 쌍 최대) | 39 % | 61 % |

**구현을 바꿔서 해결되는 문제가 아니다.** 기준 구현이 소박하다는 사실이 이 논지를
오히려 강화한다 — 정교하지 않아서 생긴 문제가 아니라는 뜻이다.

AR(1) 결과는 현장 실측(`perr` 3.4~4.4배 과소평가)과 **같은 축**이고, 합성 자료가
그것을 독립적으로 확인해 준다.

### 3-B. D 군만 구현 차이로 쓸 수 있다 — 그리고 처방은 사소하다

Augur 5/5, 기준 구현 4/5. 원인은 명확하다: 이번에 내보내기 시작한
`diag["theta_err_joint"]`(shift·squeeze 결합 표준오차) 덕이다.

그 값은 **이미 계산되던 공분산의 뒤쪽 블록**이었고 여태 버려지고 있었다.
즉 "Augur 가 더 똑똑하다" 가 아니라 **"이미 있는 값을 내보내기만 하면 된다"**
이고, 그래서 이식성이 있다. §5.5 에 그렇게 쓴다.

### 3-C. F 군 — 3차 보간이 옳은 선택이었다

F 군은 진값을 **대역제한(windowed-sinc) 부화소 재샘플링**으로 만든다. 검출기는
슬릿 함수로 이미 대역제한된 스펙트럼을 샘플링하므로 물리적으로 그 모형이 맞고,
**선형도 3차도 이것을 재현하지 않는다** — 어느 쪽도 편들지 않는 기준이다.
shift −1.96 / −0.37 / 0.41 / 2.63 px, squeeze 1.002.

| 보간자 | 중앙 오차 | 최대 | 보고 1σ(0.55 %) 대비 |
|---|---|---|---|
| 기준 구현(선형) | 6.78e-4 | 9.69e-4 | 0.12배 |
| Augur 선형 | 5.6e-4 | 1.03e-3 | 0.10배 |
| **Augur 3차(운영)** | **3.9e-5** | **1.21e-4** | **0.007배** |

**3차가 선형보다 14~17배 정확하다.** 운영 선택이 옳았다.

→ 보간 차수는 **새 예산 항이 아니라 §4.1 의 "검증했고 무시 가능" 목록**에
들어간다(ILS·T·P·블록 정착과 함께). 다만 한 줄이 붙는다: **3차 보간이 선형보다
14배 이상 정확하다.**

### 3-D. joint σ 는 B 군을 고치지 못한다

| | B noise ×1 |
|---|---|
| `perr` (조건부 선형, `<gas>_Error`) | 1.321911 |
| `perr_joint` (결합, `<gas>_ErrorJoint`) | 1.321654 |

차이 **0.02 %**. 이 케이스들은 shift 가 잘 구속돼 결합항이 거의 안 붙는다.

→ **`ErrorJoint` 를 "오차 과소평가의 해법" 으로 쓰면 안 된다.** 그 값어치는
shift 가 구속되지 않는 경우(= D 군)에 있지, 잡음 산포 교정에 있지 않다.

### 3-E. C·E — v5 지표로 보면 **E 는 뒤집히고 C 만 남는다**

v4 까지의 "Augur 가 두 군 다 더 나쁘다" 는 **최악값을 헤드라인으로 삼은 지표의
성질**이었다. 최악은 언제나 가장 약한 신호다. v5 가 지표를 검출 가능 영역
기준으로 고쳤고, 그러자 판정이 갈린다.

| | 기준 구현 | Augur |
|---|---|---|
| **E: 검출가능 쌍 최대 불일치** | 0.0465 | **0.0370 (Augur 승)** |
| C: 최대 \|편향\| (잡음 RMS 단위) | 1.374 | 1.926 |
| C: 검출가능 케이스 최대 상대편향 | 37.7 % | 44.4 % |

**E 는 Augur 가 낫다.** 창 의존성은 신호가 잡히면 사실상 사라지고(0.037 대
결합 보고σ 0.043), v4 의 0.613 은 검출한계 쌍 하나(E01)가 만든 값이었다.

**C 는 Augur 가 여전히 나쁘다 — 다만 절대량은 잡음의 0.55배다.** 두 구현의 차이는
1.926 − 1.374 = 0.55 잡음 RMS 다. 세 "누락" 케이스의 절대 편향이 거의 같다는
사실(진값이 작을수록 상대값만 커진다)이 이 군의 성질을 말해 준다.

**(가) C 군 최악값은 한 케이스가 전부이고, 두 코드 다 그 케이스를 플래그한다.**

16개 중 15개에서 Augur 편향은 0.07~4.2 % 로 기준 구현과 같은 수준이다.
593.4 % 는 `C_missing_a2e-09` 하나에서 나온다 — 그리고 그 케이스에서 **두 코드
모두 shift 를 탐색범위 끝까지 민다**:

| | shift | 보고 | 편향 |
|---|---|---|---|
| 기준 구현 | **5.00** (격자 끝) | `at_grid_edge=True`, σ=inf | −423.3 % |
| Augur | **8.00** (상자 끝) | `at_grid_edge=True`, σ_shift=2.35 px | −593.4 % |

즉 두 수의 차이는 **각자의 경계가 어디 있느냐**이지 회수 품질이 아니다.
`--shift-limit 5` 로 범위를 기준 구현에 맞춰도 558.9 % 로, 423 % 로 수렴하지
않는다 → 범위만으로 설명되지도 않는다(옵티마이저가 다르다: 기준은 0.02 px 격자
전수탐색, Augur 는 시드 13개에서 비선형 탐색).

**두 코드 다 이 케이스를 무효로 표시하는데 C 군 지표는 그 표시를 안 본다.**
벤치마크 쪽에 되돌릴 값이 있는 관찰이다.

**(나) E 군도 한 쌍(E01)이 헤드라인을 만든다.** 쌍별 불일치:

| pair | 기준 | Augur |
|---|---|---|
| E00 | 0.048 | 0.118 |
| **E01** | **0.386** | **0.613** |
| E02 | 0.014 | 0.111 |
| E03–E07 | 0.003~0.047 | 0.011~0.037 |

**보고σ 안에 든 쌍은 5/8 로 같다**(다만 든 쌍이 서로 다르다). Augur 의 불일치가
전반적으로 조금 크고, E01 에서 둘 다 실패한다.

**(다) squeeze 는 자유 파라미터가 아니었다 — 유력 후보 하나를 제외했다.**

러너는 manifest 의 squeeze 를 `sq_mode="Fix"` 로 **고정**한다. 실제 확인:

```
ref_props NO2 : {'sh_mode': 'Limit', 'sh_val': '-8.0, 8.0', 'sq_mode': 'Fix', 'sq_val': '0.002', …}
active_vars   : ['NO2_sh']          ← shift 하나뿐
fixed_vars    : {'NO2_sq': 1.002}
```

운영 FitSet 의 `sq_mode: Limit` 와 다르게, 벤치마크 실행은 비선형 자유도가
**shift 하나**다. 기준 구현과 같은 조건이므로 E 차이의 원인이 아니다.

**(라) 설정 차이 목록** — 조사하지 않은 것과 무엇이 달랐는지조차 모르는 것은
다르므로 남긴다.

| | 기준 구현 | Augur 러너 |
|---|---|---|
| shift 탐색 | [−5, 5] 0.02 px **격자 전수탐색** | 시드 13개(1 px 간격) → 상자 ±8 비선형 |
| shift 범위 | ±5 | ±8 (`--shift-limit` 로 변경 가능) |
| squeeze | manifest 값 고정 | `sq_mode="Fix"` 동일 |
| 기체 하한 | 무제약(lstsq) | `allow_negative_gas=True` 동일 |
| 에탈론 | sin·cos 두 열 | 동일(고정 f) |
| σ 의 dof | `n − (기체+차수+3)` | 엔진 자체 dof |
| 배경 | Chebyshev, `x=linspace(-1,1,n)` | 같은 차수(스팬 동일) |

제출 다 값이 내려갔다. 순위는 안 바뀐다 — Augur 가 여전히 더 나쁘다.

> **B 군은 v5 와 소수 셋째 자리까지 같다.** v7 이 B 를 안 건드렸다는 뜻이고,
> 따라서 §3-D(joint σ 는 B 를 못 고친다)와 §3-A(두 구현이 같은 방향으로 실패)는
> 그대로 유효하다.

### 5-A. B 군이 1.2 를 넘는 것과 자체 closure 0.91 — 모순이 아니다

`tools/test_varpro_closure.py` 는 백색잡음에서 산포/보고 = **0.91** 을 낸다.
벤치마크 B 는 1.322 다. 같은 코드인데 반대 방향으로 보인다. 분해했다.

**① AR(1) 은 잡음 모델이다.** ρ=0.5 → 독립화소 `(1+ρ)/(1−ρ) = 3` 배 감소 →
예측 과소평가 **√3 = 1.732**. 실측 기준 1.572 · Augur 1.649. 둘 다 그 자리고,
어느 코드도 상관 잡음 보정을 주장하지 않는다.

**② 백색 ×1 의 Augur–기준 차이는 전부 shift 자유도다.** shift 를 manifest 진값
(−2 px)에 고정하고 그 외 전부 같게 다시 돌렸다
(`--group B_noise --fix-shift`, 진단 스위치):

| | 백색 ×1 | 백색 ×2 | AR(1) |
|---|---|---|---|
| Augur shift 자유(운영) | **1.322** | 1.089 | 1.649 |
| Augur shift 고정(진단) | **1.194** | 1.115 | 1.749 |
| 기준 구현 | **1.190** | 1.325 | 1.572 |

**1.322 → 1.194 로 기준 구현(1.190)과 사실상 같아진다.** 기준은 ±5 를 0.02 px
격자로 전수 탐색하고 Augur 는 ±8 상자에 시드 13개다 — 넓은 만큼 더 떠돈다.
**공분산 식의 문제가 아니다.** AR(1) 은 고정하면 오히려 나빠져(1.649 → 1.749)
√3 에 더 붙는데, shift 자유도가 상관잡음의 일부를 흡수하고 있었다는 뜻이다.

**③ 남는 것은 케이스 설계다.** closure 의 0.91 은 **SCD 1e11~1e12 · 진 shift 0**
에서 잰 값이다. 벤치마크 B 는 **3.0e10 · 진 shift −2 px · SNR 3.2** 다. shift 를
고정해도 1.19 가 남고, 그 잔차(1.19 대 0.91)는 농도/SNR 축이다 — **아직 분리하지
않았다.** 원고에는 "서로 다른 체제" 로 쓰고 두 수치를 조건과 함께 병기한다.

### 5-B. `joint` 와 `lin` 은 B 군에서 구분되지 않는다

261케이스 전부에서 농도는 **완전히 동일**하고 보고 σ 는 중앙 **0.012 %** · 최대
1.3 % 차이다. 결합 보정은 shift 가 **안 정해질 때**(D 군) 사는 것이고, 정해질
때(B 군)는 거의 안 움직인다. 원고에서 `perr_joint` 를 파는 근거는 **D 군**이다.
