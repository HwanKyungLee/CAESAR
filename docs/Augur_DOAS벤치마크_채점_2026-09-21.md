# DOAS 합성 벤치마크 채점 — Augur (2026-09-21)

249개 합성 소광 스펙트럼(진값 기지)에 **Augur 운영 핏 경로**를 돌린 결과다.
§3(검증)의 표 원천.

## 0. 무엇과 무엇을 비교했나 — 먼저 읽을 것

비교 대상은 벤치마크 패키지에 같이 들어 있는 **`baseline.py` 하나**다.
**QDOAS 도 DOASIS 도 아니다.** README 의 자기 설명:

> 프로파일된 shift 탐색 + 열 정규화 선형해 + 공분산 기반 불확도.
> **권장 구현이 아니며**, 형식을 고정하고 넘어설 대상을 주려는 것.

즉 교과서적 최소 구현이고, 벤치마크를 만든 쪽이 같이 쓴 것이다. 독립적인 제3자
코드가 아니다. **이 표로 "Augur 가 기존 소프트웨어보다 낫다" 를 주장할 수 없다.**

기존 소프트웨어 대비 검증은 **따로 있다**:

| | 대상 | 위치 |
|---|---|---|
| 실측 교차검증 | **QDOAS** (3채널 53일) | `diagnostics/qdoas_crossval_2026-09/` |
| 실측 교차검증 | **DOASIS** | `diagnostics/doasis_crossval_2026-09/` |
| 합성 진단 능력 | baseline.py | 이 문서 |

§3 에서 "커뮤니티 코드 대비" 를 쓰려면 위 두 줄을 인용해야 한다.

## 3. 읽는 법 — 진단이 기여다

### 3-A. 두 독립 구현이 **같은 방향으로** 실패한다

이게 논문의 논지다.

| 실패 양상 | 기준 구현 | Augur |
|---|---|---|
| AR(1) 상관 잔차에서 보고 불확도 과소 | 1.57배 | 1.65배 |
| 모델 불일치 편향 / 보고 σ | 11.2배 | 9.8배 |
| 창을 바꾸면 답이 바뀜 | 39 % | 61 % |

**구현을 바꿔서 해결되는 문제가 아니다.** 기준 구현이 소박하다는 사실이 이 논지를
오히려 강화한다 — 정교하지 않아서 생긴 문제가 아니라는 뜻이다.

AR(1) 결과는 현장 실측(`perr` 3.4~4.4배 과소평가,
[measured-noise-floor-pns-2026-05])과 **같은 축**이고, 합성 자료가 그것을
독립적으로 확인해 준다.

### 3-B. D 군만 구현 차이로 쓸 수 있다 — 그리고 처방은 사소하다

Augur 5/5, 기준 구현 4/5. 원인은 명확하다: 이번에 내보내기 시작한
`diag["theta_err_joint"]`(shift·squeeze 결합 표준오차) 덕이다.

그 값은 **이미 계산되던 공분산의 뒤쪽 블록**이었고 여태 버려지고 있었다.
즉 "Augur 가 더 똑똑하다" 가 아니라 **"이미 있는 값을 내보내기만 하면 된다"**
이고, 그래서 이식성이 있다. §5.5 에 그렇게 쓴다.

### 3-C. A 군은 정확도가 아니라 **보간 차수 일치**를 잰다

| 레퍼런스 보간 | A군 최대 상대오차 |
|---|---|
| **3차 (운영)** | 2.44e-3 |
| 선형 | 0.0 |

10^10 배 차이다. 그런데 **벤치마크 전방모델이 σ 를 선형보간으로 옮겨** 스펙트럼을
만든다(README "Forward model": `sigma_g(p')` is linear interpolation). 생성기와
같은 보간을 쓰는 구현이 이기는 건 당연하고, 기준 구현이 0.0 인 것도 같은 이유다.
**A 군은 "정확한가" 가 아니라 "`generate.py` 와 같은 보간자를 쓰는가" 를 잰다.**
벤치마크 설계에 되돌릴 값이 있는 지적이다.

다만 **차수 선택이 NO₂ 를 0.24 % 움직인다**는 것은 실측이다. 운용은 항상 shift 와
squeeze 를 맞추므로 **모든 스캔이 보간된 σ 로 핏된다.** 보고 1σ 0.55 % 대비
0.44배 — §4 의 **새 항**이고, §10-B 의 블록내 추세처럼 **평균해도 안 줄어드는
고정 편향**이다. 어느 차수가 옳은지는 σ 의 부화소 거동이 정하며 이 벤치마크는
그것을 결정할 수 없다.

### 3-D. joint σ 는 B 군을 고치지 못한다

| | B noise ×1 |
|---|---|
| `perr` (조건부 선형, `<gas>_Error`) | 1.321911 |
| `perr_joint` (결합, `<gas>_ErrorJoint`) | 1.321654 |

차이 **0.02 %**. 이 케이스들은 shift 가 잘 구속돼 결합항이 거의 안 붙는다.

→ **`ErrorJoint` 를 "오차 과소평가의 해법" 으로 쓰면 안 된다.** 그 값어치는
shift 가 구속되지 않는 경우(= D 군)에 있지, 잡음 산포 교정에 있지 않다.

### 3-E. C·E 는 Augur 가 더 나쁘다

| | 기준 구현 | Augur 운영 |
|---|---|---|
| C 최대편향 (흡수체 누락) | 423.3 % | **593.4 %** |
| E 창간 최대 불일치 | 0.386 | **0.613** |

원인은 추적하지 않았다(§3 을 "진단이 기여" 로 쓰기로 했으므로 구현 우열을 다툴
자리가 아니다). 그대로 보고한다.

⚠ C 군에서 **Augur 는 편향이 더 크지만 편향/σ 비는 더 작다**(9.79 < 11.16).
Augur 의 보고 σ 가 그만큼 크기 때문이다. **분모가 다른 두 수라 어느 쪽이 낫다고
읽으면 안 된다** — 둘 다 "보고 불확도가 모델 불일치를 못 덮는다" 는 같은 결론을
준다. 그게 이 군의 요점이다.

## 4. 이 실행이 낳은 코드 변경

| | 무엇 | 왜 |
